00這一版改了什麼

v1（2026-09-07）之後改了幾件事。「已上線」的那兩列是 v1 文件已經跟實作對不上的地方，照 v1 寫的程式現在就會失敗。

項目v1v2狀態
上傳路徑的欄位mission_idplan_id——09-08 改名後服務端只收這個名字已上線
/api/start 的回應範例寫 mission_id實際回 plan_id、name、steps（§6）已上線
名詞「任務」同時指航線分成路徑、任務、架次三個（§1）—
起飛參數mission（其實是路徑）plan_id（路徑）＋ mission_id（任務 UUID）；mission 暫留為別名已上線
即時資料輪詢 /api/ext/liveWebSocket 串流，從起飛開始每 0.5 秒推送（§8）。快照的欄位全部併進串流的 state（對照表），快照 /api/ext/live 在串流實飛驗收後移除已上線
錯誤回應只保證 detail.msg/api/start 與群飛執行一律 code＋msg，能自己排除的再附 how_to（§15）已上線

01名詞與連線方向

路徑（plan）任務（mission）架次（session）
是什麼一份航線：航點、高度、速度一件要做完的事一台機從解鎖到上鎖
誰建立在規劃頁畫，或匯入 .plan人宣告：外部控制端在起飛時帶編號；我們的畫面在起飛時問系統自動：解鎖就有、上鎖就結束
範圍可以飛很多次可以有多台機、多個架次一台機、一顆電池
編號plan_idmission_id（UUID，可由控制端產生）session_id

誰連誰：外部控制端連到地面站，地面站不會主動連出去。地面站有兩個服務：

埠服務本文件用到的
38001指令（command）無人機清單、路徑清單、上傳、起飛、切模式
38000資料（backend）即時串流、架次匯出

時間一律是地面站時鐘（UTC、ISO 8601）；座標是 WGS84。

任務相關的錯誤

HTTPcode什麼時候msg 說明什麼
422mission_id_invalidmission_id 不是 UUID收到的值、要的格式（例如 crypto.randomUUID() 產生的）
409mission_ended這個任務已經結束任務名稱與結束時間；要再飛就產生新的 UUID
409mission_busy這台機已經在另一個進行中的任務裡那個任務的名稱與編號
409mission_name_takenmission_name 與既有任務同名（不分大小寫）撞名的是哪一個任務
422plan_requiredplan_id 與 plan 都沒給或都給了兩者的差別
409drone_unknown這個 sysid 在地面站還沒有機體記錄等收到心跳再試

mission_id 對到一個進行中的任務時，這次起飛就掛到那個任務底下（例如群飛裡補飛一台）。不帶 mission_id 而這台機已經在某個進行中的任務裡，也直接掛進那個任務。

08即時串流

控制端自己產生一組 UUID 當任務編號，用它連上串流，再帶著同一組編號起飛。 從起飛流程開始每 0.5 秒收到任務裡每一台機的狀態，外加預計航線、已飛過的軌跡與重要事件，拿來在自己的 OSM 地圖上畫。串流只讀，不收指令。

WSws://10.141.2.21:38000/ws/v1/missions/{mission_id}已上線

一條連線看一個任務底下所有機的所有架次。群飛時也是一條。

query

keyvalue資料格式
after_seq1842int · 選填
重連時帶最後收到的序號（§12）

尚未實飛驗收。連線、等待、結束、重連補送、錯誤關閉都已經對正在跑的地面站測過；解鎖、離地、著地、上鎖事件的時序與墜機判定，要真的飛一趟才算數。

流程

1控制端產生一組 UUID，當任務編號
2控制端→地面站連 /ws/v1/missions/{UUID}。回 hello（waiting），之後每 0.5 秒一則保持連線
3控制端→地面站30 秒內呼叫 POST :38001/api/start，帶 {"plan_id": …, "mission_id": UUID}。地面站用這個 UUID 建立任務
4地面站→控制端route（預計航線）、每 0.5 秒 state、event——上傳、解鎖、爬升都看得到
5地面站→控制端最後一台上鎖 3 秒後：自動結束任務、送 ended、關閉連線
  • 先連再起飛。/api/start 要等飛機爬到起飛高度才回應，先連上，上傳、解鎖、起飛那一段才看得到。
  • 群飛：POST :38001/api/command/group/{group_id}/execute 同樣帶 {"mission_id": UUID}。不帶 mission_id 也不帶 mission_name 時照舊不建任務（畫面按的群飛就是這樣）。
  • 看從我們畫面啟動的任務：GET :38000/api/missions/active 拿到任務編號，連同一個網址。這種任務由操作員在畫面上結束。

階段 phase

phase什麼時候
waiting已經用這組 UUID 連上，還沒有人用它呼叫起飛。最多等 30 秒，逾時送 ended（never_started）並關閉
starting收到 /api/start 那一刻起（不是等它回應），還沒有任何一台離地
active至少一台解鎖中
ended任務結束（§10），送出 ended 後連線關閉

09訊息格式

全部是 JSON 文字訊息。每一則都有下面這幾個欄位；seq 在同一個任務內所有型別共用、嚴格遞增，補送就靠它。只屬於一條連線的訊息不帶 seq：hello，以及連上時補的 route、track。seq 不從 1 開始，只保證遞增。

共同欄位
{"v": 1, "type": "state", "mission_id": "8f0c…", "seq": 1843, "ts": "2026-09-14T07:30:12.500Z"}
type什麼時候送
hello連上時第一則，不帶 seq
route預計航線。起飛流程開始時、連上或重連時、飛行中改航線時。群飛每台一則
track已經飛過的實際軌跡。連上或重連時一次（不帶 seq），之後用 state 的位置接著畫
state固定每 0.5 秒，沒有變化也送
event重要變化發生時
ended任務結束，之後連線關閉
error以錯誤關閉連線之前

10任務何時結束

3秒

用 /api/start 建立的任務：每一台都已上鎖，最後一台上鎖 3 秒後自動結束任務、送 ended、以 1000 關閉。這 3 秒內任何一台又解鎖，就不結束。

  • 要換電池再飛：開一個新任務（新的 UUID）。
  • 從我們畫面建立的任務：由操作員在畫面上結束時才送 ended，兩趟之間照常每 0.5 秒送狀態。
  • 3 秒夠用是實測過的：這台 ArduCopter 4.7 用路徑的降落項或 LAND 模式降落，著地後 0.4–0.8 秒就自動上鎖（2026-09-14 五次降落）。手飛直接落地、RTL 降落還沒有樣本。

每一台的結束原因 reason

reason意思
landed著地後上鎖：著地狀態先到 on_ground，接著上鎖
crash飛控判定墜機而切斷馬達。控制端必須分得出落地與摔機
disarmed_in_air上鎖時沒有著地訊號，例如飛控其他保護機制上鎖
telemetry_lost解鎖中連續 90 秒沒有遙測，地面站收掉這一趟。不代表飛行結束，只代表資料在那裡斷了
start_failed起飛流程被拒（上傳、解鎖、起飛任一步）
aborted群飛全撤

不會結束的情況

  • 著地了但一直沒上鎖（例如手飛落地、油門沒拉到底）：繼續送，該機 landed: "on_ground"、armed: true。
  • 路徑最後沒有降落項（例如從 QGC 匯入的）：飛機會在最後一點懸停，串流一直開著，直到有人讓它降落。本系統規劃頁產生的路徑一定帶降落項。
  • 控制端斷線：不影響飛行，也不影響任務何時結束。

113 秒斷線規則

3秒

超過 3 秒沒有收到任何一則訊息，就當成連線斷了：關掉這條連線，帶著最後收到的 seq 重連。

地面站保證每 0.5 秒一定送一則——waiting 時送保持連線用的 state，起飛後送真正的 state。3 秒是正常間隔的 6 倍，一般的網路抖動不會誤判。

為什麼不能等 WebSocket 自己報錯：網路半路斷掉時（5G 或跨網段的路由掉包），TCP 可能要好幾十秒才發現對方不在了。那段時間連線看起來還開著，地圖上的飛機卻停在原地——看起來像懸停，其實是資料沒有進來。

判斷斷線後，把地圖上的機體標成「資料中斷」，不要讓它停在最後的位置看起來正常。範例見 §16。

這裡的「連線斷了」與 §13 的「資料舊了」是兩件事：連線好好的，飛機的遙測也可能斷了。

12重連與補送

地面站為每個任務保留最近 60 秒的訊息。重連時帶上最後收到的序號：

重連
ws://10.141.2.21:38000/ws/v1/missions/8f0c2d1e-5b7a-4c1e-9d3f-2a6b8c4e0f11?after_seq=1842
1hello漏掉的比緩衝還舊時，replay.gap 說明缺了哪一段：{"from_seq": 1843, "to_seq": 1990}
2route當下的預計航線
3track完整的實際軌跡——軌跡不會缺
4緩衝訊息序號大於 after_seq 的，每則帶 "replay": true
5即時接回每 0.5 秒的 state
  • 缺的是那段期間的事件與逐則狀態，照實用 gap 說出來，不假裝沒缺。地面站重啟時緩衝也會不見。
  • ended 送出後緩衝再保留 30 秒：在最後幾秒斷線的控制端，重連還拿得到 ended；超過 30 秒才重連會收到 error 與 4410。
  • 一個任務可以同時有多個控制端連上；慢的控制端不會拖慢別人，它自己的佇列滿了會先丟最舊的 state（其他型別不丟），下一則 state 帶 "dropped": N。

13過期資料

與地面站自己的畫面同一套規則。一個照常顯示的舊數字比沒有數字更危險——曾經有畫面顯示「解鎖中、降落模式、高度 1.07 m」，實際上是兩個半小時前的殘影。

freshnessage_s送什麼
live< 2全部照送
stale2–10全部照送，由 freshness 標明。控制端應該把那台機畫淡
old> 10除了身分、freshness、age_s、connected、link 以外全部是 null（位置、朝向、速度、模式、解鎖、著地、任務進度、電量、GPS）；最後已知位置放在 last_known：{"lat", "lon", "alt_rel", "at"}

old 時把位置拿掉而不是只加標記，是為了讓人讀不到那個數字——一個標著「舊」的座標，仍然會被畫成「飛機在這裡」。

兩趟怎麼對齊

時間對不齊：兩趟的速度不同，用時間當 X 軸會把「同一個地點」錯位。每一筆樣本都投影到那一趟自己的預計航線上，給出 along_m（走了多遠）與 offset_m（偏離多少），控制端拿 along_m 當共同的 X 軸。

  • 基準是計畫航點，不是任一趟的實飛軌跡——拿其中一趟當基準，那一趟的偏航就變成零誤差。所以那一趟沒有綁路徑時 reference 是 null、along_m 全給 null，不退回用軌跡。
  • 偏離超過 max_offset_m（預設 60 m）的樣本 along_m 給 null，offset_m 照給。硬塞進某個里程的數字看起來完全正常，而且沒有線索說它是垃圾。
  • along_m 只在同一份路徑之間可比。每一趟都帶 plan_id，比較前先確認相同。
  • gaps 是超過 10 秒完全沒有資料的區間。與「訊號差」是兩件事：畫圖時要留白，不要把兩端連成一條線。

只有掛在任務底下的架次拿得到。用 /api/start 帶 mission_id 起飛的一定有；更早以前的飛行多半沒掛任務，要先在畫面的資訊頁補歸。

15錯誤格式與狀態碼

失敗一律回 4xx／5xx。每一個錯誤都同時帶機器讀的 code 與人讀的 msg，呼叫端自己排除得了的再附 how_to。msg 可以直接顯示給人看。

409
{"detail": {
  "code": "mission_busy",
  "msg": "這台機（sysid 1）已經在進行中的任務「0914 巡檢」（8f0c…）裡，一台機同一時間只能在一個任務",
  "how_to": ["等那個任務結束再起飛", "或改用 mission_id 8f0c… 起飛，把這一趟掛進那個任務"]}}

/api/start 與群飛執行的錯誤一律是物件、一定有 code 與 msg；沒有專屬代碼的依 HTTP 狀態給通用代碼（forbidden、not_found、conflict、vehicle_rejected、timeout…），起飛後判定不到離地是 not_airborne。其他端點（上傳、切模式）形狀照舊：detail 是字串就直接顯示，是物件就顯示 detail.msg。

狀態常見 code意思怎麼辦
403not_admitted這台機不接受指揮（例如沒有機上代理），或地面站的指令功能沒開先查 §3 的 controllable 與 reason
404—找不到這份路徑／航線檔用 §4 重新取清單
409guard_refused、unverified、mission_busy…當下狀態不允許（例如飛行中上傳、機在地面卻叫它開始路徑），或做了但沒能讀回確認照 msg 與 how_to 換做法
422mission_id_invalid…payload 欄位缺漏或型別不對對照該端點的 payload 表
501—這個機型的這個動作尚未支援換動作或換機
502—飛控拒絕，或沒有回 ACK看 msg；沒有 ACK 可重試
504link_timeout指令送出去了，但 30 秒內沒有回應——送往飛機的方向不通可重試；連續失敗代表通訊中斷
503—沒有任何無人機在線查 §3

16範例程式

最小的控制端（Leaflet）：先連串流、再起飛；畫預計航線、實際軌跡與機體位置；3 秒沒收到訊息就標成資料中斷並重連。

javascript
const GS = "10.141.2.21";
const missionId = crypto.randomUUID();
let lastSeq = null, ws = null, watchdog = null;
const markers = {}, tracks = {};

function connect() {
  const q = lastSeq == null ? "" : `?after_seq=${lastSeq}`;
  ws = new WebSocket(`ws://${GS}:38000/ws/v1/missions/${missionId}${q}`);
  ws.onmessage = (e) => {
    const m = JSON.parse(e.data);
    if (m.seq != null) lastSeq = m.seq;
    resetWatchdog();
    if (m.type === "route") L.geoJSON(m.geojson).addTo(map);              // GeoJSON：[經度, 緯度]
    if (m.type === "track") {
      tracks[m.drone_id]?.remove();
      tracks[m.drone_id] = L.geoJSON(m.geojson, {style: {color: "red"}}).addTo(map);
    }
    if (m.type === "state") for (const d of m.drones) {
      const p = d.position ?? d.last_known;                                // old 時位置在 last_known
      if (!p) continue;
      markers[d.drone_id] ??= L.marker([p.lat, p.lon]).addTo(map);        // Leaflet：[緯度, 經度]
      markers[d.drone_id].setLatLng([p.lat, p.lon])
        .setOpacity(d.freshness === "live" ? 1 : 0.4);
    }
    if (m.type === "error") console.warn(m.code, m.msg);
    if (m.type === "ended") { clearTimeout(watchdog); ws.onclose = null; }
  };
  ws.onclose = () => setTimeout(connect, 1000);
}

// §11：3 秒沒收到任何訊息＝連線斷了，不等 WebSocket 自己發現
function resetWatchdog() {
  clearTimeout(watchdog);
  watchdog = setTimeout(() => {
    for (const mk of Object.values(markers)) mk.setOpacity(0.2);          // 標成「資料中斷」
    ws.close();                                                            // onclose 會帶 after_seq 重連
  }, 3000);
}

connect();
const r = await fetch(`http://${GS}:38001/api/start`, {method: "POST",
  headers: {"Content-Type": "application/json", "X-Client": "my-controller"},
  body: JSON.stringify({plan_id: "0914-square-test-v5", mission_id: missionId})});
if (!r.ok) { const {detail} = await r.json(); alert(`${detail.code}：${detail.msg}`); }

17不提供的東西

  • 沒有認證。任何連得到地面站的人都能看任何一個任務的即時狀態，也能指揮飛機。安全靠網段隔離——這件事要寫在這裡，不能靠「大家都知道」。
  • 串流不收指令。暫停、返航、改航線照舊走 :38001。
  • 不送圍欄。控制端只拿預計航線與實際軌跡。
  • 歷史不做伺服器端的比較結論（勝負、改善多少）：地面站給樣本與共同的 X 軸，怎麼比是控制端的事。也不做 CSV、不降採樣。
  • 不再提供輪詢快照 /api/ext/live：即時資料只走串流（v1 §5 的那一支，串流上線時移除）。
  • 不送影像、不送原始 MAVLink、不送 IMU 或驅動診斷這類內部欄位。
  • 逐則訊息只補送 60 秒；更早的完整資料走 GET :38000/api/sessions/{session_id}/export。
