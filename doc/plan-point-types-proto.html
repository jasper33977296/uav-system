點位類型與存檔

三件事，前兩件是同一個原因。

①②「看不出哪個是起飛點」＝「一個點就有線」

放一個點時畫面上其實有三個點：起飛點（在你填的經緯度上）、你放的那個、 以及回起飛點降落。線是 起飛點 → 你的點 → 回起飛點，所以線沒有錯—— 錯的是三種點長得一樣，於是看起來像「一個點卻有線」。

現況全部都是藍球，分不出來
G接地點一種顏色，靠形狀分起降 我建議這個
起飛點：空心環＋地面十字 航點：實心球 降落點：向下三角

綠色＝會接地的點（起飛與降落是同一類事），形狀分是哪一種： 起飛是「從這裡上去」用環＋十字（那也標出它拖不動——位置是解鎖的地方， 不由規劃決定）；降落是「往這裡下來」用向下三角。藍色球維持現況＝飛過去的點。
顏色只用三個，而且不動橘色——橘在這套系統裡是互動 chrome 與「假設值」的顏色，拿來當點位類型會撞。

H三種顏色，形狀都一樣

最省事，但**斜角俯視 ＋ 小球**時顏色比形狀難分，而且黃色會跟 「假設高度的建物」「返航高度」撞。

③ 既有航線：儲存／另存新檔，標題雙擊改名

現況只有「另存新檔」（原本的裁定是「改動不會動到原本那份」）。 你要加回「儲存」，那等於改掉那條裁定——所以要講清楚它的後果。

I兩顆鈕 ＋ 雙擊標題改名 我建議這個
平常（雙擊標題可改名）：
0908-snake-v1 │ 最低離地 2 m返航 4.6 m
雙擊之後：
Enter 存・Esc 取消
改過航點之後（底下那一列）：
已改 3 個航點——只在畫面上

「儲存到這一份」會蓋掉原本的航點，而且讓那一份的人工審查失效 （簽核綁在 waypoints_hash 上）——按下去要跳一次確認，訊息就寫這句。
另存新檔仍然是主要動作（橘色那顆）：原本那條裁定的理由還在 ——飛過的那一份是紀錄，改它等於改歷史。
