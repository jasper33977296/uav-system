# 例外狀況處理 · 檢測流程表

> **三層防線分別住在三個不同的地方，而原本沒有一個地方看得到它們現在是開是關。**
> 飛控那層在參數裡、代理那層在 systemd 的 `Environment=`、地面那層在容器裡。
> 2026-09-02 的實測就是這樣被漏掉的：`BATT_FS_LOW_ACT=0`（低電量偵測得到
> 但**不動作**）躺在那裡不知道多久，而畫面上一切正常。
>
> 機器查得到的部分：`python3 scripts/check-failsafes.py`。
> **但它只能回答「設定是開的」，回答不了「它真的會動作」**——後者只有
> §4 的實體驗證做得到。這兩件事在這張表裡刻意分開，因為把前者當成後者
> 正是這類系統出事的方式。

結果只有三種：`PASS`（判準那欄寫的，親眼看到了）、`FAIL`、
`SKIP`（**skip ≠ pass**，沒測就是沒有證據）。

## 第 0 段 · 先確定你讀到的是這台機的設定

| # | 查核項 | 判準 | 為什麼 | 結果 |
|---|---|---|---|---|
| 0.1 | 參數來源可信 | 用 `--dev` 直接問飛控；或用 `--tlog` **且一定要 `--sysid`** | 地面站錄的 tlog 是**那個埠上的所有流量**。2026-09-02 實測：一份 tlog 裡 sysid 1 有 2031 個參數、sysid 2 有 975 個——不濾就會把**另一台機的設定當成這台的** | |
| 0.2 | 參數不是舊的 | `--tlog` 的每一列會印出「幾分鐘前」 | **tlog 裡的參數只在有人問過時才更新。** 實測：用序列埠改完六個參數後，只有代理開機會重問的那兩個在 tlog 裡變新，另外四個還是舊值——**看起來像沒改成功** | |
| 0.3 | 電芯數已確認 | 有人**看過那顆電池**並填進 `--cells` | 從遙測看到的最高電壓推電芯數，**在接電源供應器時完全失效**（2026-09-02 踩過）。`BATTERY_STATUS.voltages[]` 只有 `[0]` 有值＝沒有單電芯監測，推不出來 | |

| # | 參數 | 判準 | 沒過的意思 | 結果 |
|---|---|---|---|---|
| 1.1 | `BATT_MONITOR` | ≠ 0 | 完全沒在量電池，下面每一格都不存在 | |
| 1.2 | `BATT_FS_LOW_ACT` | ≠ 0（2＝RTL） | **0＝None：偵測得到但不動作。** 它仍會在地面擋你解鎖，**但在天上什麼都不做** | |

| 1.4 | `BATT_LOW_VOLT` | 3.3–3.7 V/cell | 設給另一種電池的話，不是永遠觸發就是永遠不觸發。**原值 10.5 是 ArduPilot 的 3S 預設** | |
| 1.5 | `BATT_CRT_VOLT` | 3.0–3.5 V/cell 且 < `BATT_LOW_VOLT` | 0＝critical 那層連門檻都沒有 | |

| 1.8 | `FS_GCS_TIMEOUT` | > 代理的單飛上限 | 太小的話飛控會搶在代理前面，「失聯後跑完任務再 RTL」那一格永遠不會發生 | |
| 1.9 | `FS_EKF_ACTION` | ≠ 0 | EKF 發散＝飛機不知道自己在哪，而它還在按那個位置飛 | |

## 第 4 段 · 實體驗證（**機器查不到，只能真的做一次**）

> **上面三段全部 PASS，只證明「設定是開的」。** 這一段才回答
> 「它真的會動作嗎」。兩者之間差著一整條沒有人走過的路徑。

| # | 查核項 | 怎麼做 | 判準 | 結果 |
|---|---|---|---|---|
| 4.1 | 遙控器失聯真的會動作 | 起飛懸停後**關掉遙控器** | 飛控在 `FS_THR_*` 設定的時間內進入設定的模式；事件流看得到 | |
| 4.2 | 地面失聯：代理先動手 | 起飛後拔掉地面站的 5G | **代理**在 `LINK_ACTION_S` 後依狀態處置，而不是飛控在 45 秒後才動——順序錯了代表不變式沒有生效 | |
| 4.3 | 地面失聯：代理掛掉時飛控接手 | 起飛後 `systemctl stop uav-agent` | 飛控在 `FS_GCS_TIMEOUT` 後動作。**這一格驗的是後備，不是主路徑** | |
| 4.4 | 低電量真的會 RTL | 飛到 `BATT_LOW_VOLT` 以下（**在安全高度、場地淨空**） | 進入 RTL；`PreArm`/事件流說得出原因 | |
| 4.5 | 電量百分比可信 | 見 §5 校正 | 落地後的回報剩餘與充電器充回去的量對得上（±10%） | |
| 4.6 | 圍欄真的會擋 | 若 1.13 啟用：朝邊界飛 | 在邊界前被擋下並執行 `FENCE_ACTION` | |

## 第 5 段 · 電池校正（做完 4.5 才有意義）

**`battery_remaining` 完全來自電流積分，與電壓無關**——實測
`(BATT_CAPACITY 3300 − consumed 1381) / 3300 = 58.2%`，飛控回報 58%。
所以電流刻度不準＝畫面上那個百分比不準，而它是畫面上最顯眼的數字。

> **一定要接要飛的那顆電池，不能在電源供應器上做。** 接電供時電壓是人調
> 出來的、不是放電曲線，而校正的每一步都建立在「電壓變化反映放電」上。

1. **先校電壓**（低電量門檻靠它）：電表量電池 → `calibrate-battery.py --volts <量到的>`
2. **再校電流**：充飽 → 飛掉 50–80% → 記下飛控說的 mAh → 充電器充回滿記下 mAh
   → `calibrate-battery.py --charged-mah <充回的> --reported-mah <飛控說的>`
3. **零點**：`--check` 看靜置時累積消耗還會不會長。注意累積消耗是**整數 mAh**，
   窗太短會被量化誤差蓋過（靜置 0.2 A 時要 30 分鐘以上）；或用 `--tlog`
   從地面站的錄製算，**不必停代理**。
4. 校完才有資格開 `BATT_LOW_MAH` / `BATT_CRT_MAH`。
