# 路徑規劃頁：重新設計（2026-09-09，設計稿）

> 延續 `doc/route-planning-first-principles.md`。**那份拆的是「條件」（C1–C9），
> 這份拆的是「流程」。** 條件逐條都做了，錯的是流程。

## 0. 為什麼要重來一次

上一份導出的功能（剖面圖、逐段表、低空帶速擋門、從零產生）都做了、也都在跑。
但**編輯的單位仍然是航點**，那是 QGC 的模型——我們只是把儀表做得比較好。
三個證據都在程式裡：

1. **右欄第一個欄位是「高度（離起飛點）」。** 我們花一整份文件說「離起飛點
   是害你摔機的那個基準」，然後把它當成主要輸入放在最顯眼的地方。
2. **從零產生的表單要你在放第一個點之前就填「起飛高度」與「速度」。**
   那時你還沒看到地面長什麼樣。順序是反的。
3. **`build_plan()` 幫你插了起飛項、`DO_CHANGE_SPEED` 的位置、降落項、
   glide 的中繼點——頁面一個字都沒說。** 上一份的 F2 明文要求
   「系統替你決定了什麼必須逐條可見且可改」，這件事完全沒做。

第四個是結構缺口：`plans` 有 `status`（draft/uploaded/…），
**但沒有任何一欄記得「這一份檢查過沒有、在什麼假設下檢查的、誰決定照飛」**。
C9 說所有檢查的價值取決於上傳前被看到——而這頁在上傳之前就結束了。

## 1. 第一原理：只有操作員知道的是哪幾件事

問法要換。不是「規劃需要哪些參數」，而是
**「哪些事情只有人知道？其餘全部該由系統負責。」**

| 只有人知道 | 是什麼 | 現在問了嗎 |
|---|---|---|
| **去哪** | 任務關心的地點／範圍 | 有 |
| **為了什麼** | 拍立面／掃面／A 到 B——決定路徑的**形狀** | 沒有（本次不處理，見 §10） |
| **可接受的貼近程度** | 今天離東西多近可以 | 混在「高度」裡 |
| **時間預算** | 要不要在 N 分鐘內回來 | 沒有（本次不處理） |

其餘**全部可以推導**：`frame`、逐點 `alt`、`DO_CHANGE_SPEED` 放哪、
`WP_RADIUS` 的交互作用、RTL 高度、起飛高度、降落方式、取樣密度。
`build_plan()` 已經在推導大部分了——但 UI 還在問其中兩個，
而且讓你逐點改高度，等於把 frame 問題換個樣子端回來。

**錯配**：操作員的意圖單位是**整條路**或**一段**；系統要求的輸入單位是
**一個點**。「下一段速度」掛在航點上，那是 `DO_CHANGE_SPEED` 的實作細節
漏到畫面上。

## 2. 使用者裁定（2026-09-09）

1. **逐點編輯要留著。** → 政策 ＋ 例外（§4），不是二選一。
2. **先畫線；高度預設「比該地形高 3 m」。** → 動作順序反轉（§3），
   而且預設的高度政策是**離地面**（§5）。
3. **撞到東西給選項，不自動繞。** → §6。
4. **檢查結果要落庫、上傳前要擋。** → §7。

## 3. 新流程：四個動作

### 動作 1 — 說要去哪（只有 x/y）

在 3D 上畫**地面軌跡**。沒有高度、沒有速度。底下是正射影像 ＋ 地形 ＋ 建物，
所以「這條線會穿過 51 館」在畫的當下就看得見，不是按了試算才知道。

**畫完就已經是一條合法航線**：高度套預設政策（離地 3 m），速度套預設，
起飛／降落／`DO_CHANGE_SPEED` 由系統補。**沒有一個欄位需要先填。**

### 動作 2 — 說要怎麼飛（整條路一個政策）

* **高度政策**三選一，預設第一個：
  * **離地面 N m**（預設 N = 3）
  * 離起飛點 N m
  * 固定海拔 N m
* **速度**一個數字。

政策改了，**沒有被標成例外的點全部跟著變**。

### 動作 3 — 攤開「系統替你決定了什麼」

一張逐條可見、逐條可改的表。至少要有：

| 項目 | 系統決定的值 | 為什麼 |
|---|---|---|
| 起飛高度 | 1.5 m | `MIN_TAKEOFF_ALT_M` |
| 每個航點的 frame／alt | frame 3、逐點不同 | 高度政策是「離地面」（§5） |
| `DO_CHANGE_SPEED` 放哪 | 第一個航點**之前** | 不然起飛那一段會用機上 `WP_SPD` |
| 降落方式 | 飛到定點再垂直降落 | 預設 |
| RTL 高度 | 讀機上 `RTL_ALT_M` | 失效處置也在同一片地形上發生（C7） |

**改任何一條就變成例外並標記。** 這是上一份 F2 承諾但沒做的東西，
而且是四個動作裡最便宜的一個。

### 動作 4 — 不通過的地方變成選擇，不是報告

現在是一串 ✗ 給你自己想辦法。改成**每一條發現配動作**（§6），
選了就記進這一份（§7）。

## 4. 政策與例外：逐點編輯怎麼活下來

使用者要保留逐點編輯。它的位置是**例外機制**：

* 每個航點有 `alt_source`：`policy`（跟著政策）或 `manual`（手動改過）。
* **改政策不動 `manual` 的點。** 這是整個機制的重點：把高度政策從 3 m
  調到 5 m，那個你特意壓到 1.5 m 的低空段**不會被偷偷抬起來**。
* 畫面上兩者要分得出來（跟著政策的點是一種樣子，例外是另一種），
  而且**每個例外都要有一鍵「收回，跟著政策」**。
* 剖面圖與逐段表上，例外的那幾段要標出來——不然「為什麼這一段特別低」
  這個問題只能靠記憶回答。

> 這條紀律與建物那邊同源：`height_source`、`speed_src`、`assumed_m` 都是
> 「這個數字打哪來」。**`alt_source` 是同一件事在高度上的樣子。**

## 5. 「離地面 N m」不需要 `frame 10`

**技術提案。** 操作員說「離地 3 m」，系統用自己的 DEM 逐點算出 AMSL，
**寫成 frame 3 的航線**——每個航點的 `alt` 各不相同，但飛出來是貼著地形的。

為什麼值得這樣做：

* 自然的心智模型（「離我下面的地 3 m」）在**任何飛控上都成立**，
  不必賭它有沒有地形圖庫。C2 那整條分支（`check_terrain_ready`、
  `RTL_ALT_M` 核對、兩秒後轉返航）**在這條路上不存在**。
* 它直接修掉 2026-09-07 的成因：使用者要的一直是這個，
  航線寫的是「離起飛點」。

**誠實的代價，要寫在畫面上：**

* 預算出來的貼地只有我們 DEM 那麼準（SRTM 30 m ＋ OSM 建物）。
  **取樣點之間可能錯。**
* `frame 10` 交給飛控，它那份也是 SRTM 級的。
  **兩條路都不是真正的地形跟隨**——那要測距儀。
* 所以 `frame 10` 不刪，它仍然是「讓飛控自己跟」的那個選項；
  差別是**預設不再需要它**。

### 5.1 「離地面」的地是哪個地——這一條要講死

`Sample` 有 `ground`（地形）與 `top`（含建物的表面）。政策用的是
**`ground`（地形）**，不是 `top`。

理由：本場域八成建物的高度是假設值（`doc/field-3d-model-design.md` §8.2.1）。
「自動爬到屋頂上 3 m」會產生一條**看起來安全、但基礎是猜的**路徑，
而且它悄悄地做了使用者裁定 ③ 說不要的事（自動繞開）。
**建物是發現，走 §6 的選項路徑，不是政策自動處理掉的東西。**

## 6. 撞到東西 ＝ 選擇（使用者裁定 ③：給選項，不自動繞）

每一條發現配一組**具體動作**，按下去直接改這一份（仍然是「另存新檔」才落地）：

| 發現 | 選項 |
|---|---|
| 穿地／離地不足 | **抬高這一段** ／ **整條抬高** ／ 我知道，照飛 |
| 低空帶速 | **降這一段的速度到 V** ／ **抬高這一段到 H** ／ 我知道，照飛 |
| 穿過已知高度的建物 | **抬到屋頂上 N m** ／ **繞開**（給一條建議路徑，人按了才採用） ／ 我知道，照飛 |
| 穿過高度未知的建物 | **套用假設高度**（§8.2.1 的旋鈕） ／ **繞開** ／ 我知道，照飛 |
| 轉角過衝 | **降速** ／ **把轉角拉開** ／ 我知道，照飛 |

「繞開」給的是**一條建議**，畫在圖上讓人比較，**按了才採用**——
不是系統自己改。這正是裁定 ③ 的 (b)。

> **為什麼不做 (c)（系統直接繞）**：在建物高度有八成是假設值的情況下，
> 自動繞會產生一條看起來很聰明、但基礎是猜的路徑。§7-6 的 3D 規劃器
> 要等建物高度是量出來的（光達）才有意義。

## 7. 檢查結果落庫 ＋ 上傳閘門（使用者裁定 ④）

現況：`mission_upload` **每次上傳都會重跑一次幾何預檢**（`terrain_enforce`
預設 `True`，穿地就 409）。那一層是對的，也是最後一道。

**缺的不是檢查，是「操作員決定過什麼」。** 上傳那一刻分不出
「沒人看過」與「看過、按了照飛」，所以它只能全擋或全不擋。

要加的是一份**簽核紀錄**，跟著航線走：

```
plan_checks
  plan_id        誰
  checked_at     什麼時候
  ok             那一次的結論
  assumed_m      在什麼假設下（未量測建物）
  limits         用哪組門檻（LOW_ALT_M／LOW_SPEED_MS…）
  wp_spd         速度是讀到的還是沒讀到
  acknowledged   逐條「我知道，照飛」的清單（哪一條、誰、什麼時候）
  waypoints_hash 綁在哪一版航點上
```

`waypoints_hash` 是關鍵：**航點一改，簽核就失效**。不然簽核會變成
「曾經有人在某個版本上按過 OK」這種沒有意義的東西。

上傳時的規則：

* 有簽核、`ok`、hash 對得上 → 照現在的流程走。
* 有簽核、不 `ok`，但每一條 problem 都在 `acknowledged` 裡 → 放行，**留痕**。
* 沒簽核，或 hash 對不上 → **擋**，訊息說「這一份改過之後沒有人看過檢查結果」。

### 9.1 做的時候量到、設計稿沒寫到的三件事

**都是「政策說對了、但整條航線做不到」的同一類問題**，而且三件都是
寫測試或看畫面時才冒出來的，不是想出來的。

1. **逐點貼地 ≠ 整段貼地。** 兩個航點之間隔著土坡，直線飛過去就低於政策
   ——預設政策產生的航線自己會被 `check_terrain` 判穿地（−1.5 m）。
   解法是 `_fill_terrain()`：每次找這一段虧最多的地方插一個中繼點，
   有上限（每段 8、總共 60），插了幾個要說。
2. **起飛高度沒跟著政策。** 用 1.5 m 起飛再飛向 3 m 離地的航點，中間在
   地面爬升處貼到 0.3 m。起飛高度改成預設跟著政策。
3. **降落前沒有進場點。** 最後一段用前一個航點的高度飛過去，降落點在
   低窪處就一路貼地（實測 0.6 m）。補一個降落點正上方、還在政策高度的
   進場點。

三件補完之後，同一條航線**每一段都剛好 3.0 m 離地**（含爬升與進場）。

### 9.2 例外的粒度是「操作員畫的那一段」

`resolve` 回來的 `seqs` 可能落在**中繼點**上，而中繼點是每次重算出來的
——改它沒有意義。所以套用時一律往外找：把目標 seq 夾在中間的那兩個
**操作員點**變成例外。速度例外同理，粒度也是操作員畫的那一段。

## 12. 失效處置：返航畫在同一張剖面圖上（2026-09-09，C7 的通則化）

**一條航線不是只有「照著飛」一種未來。** 失聯、低電、地形資料沒了，各自
觸發一個處置，而那個處置在同一片地形上發生。上一份的 C7 只在 `frame 10`
那條路上做到了（`check_terrain_ready`），其實它是通則。

### 12.1 ArduCopter 的返航實際上做什麼

1. 爬到 `RTL_ALT_M`——**離起飛點，不是離地形**（與 `RTL_ALT_TYPE` 無關）。
   而且它是**下限不是目標**：飛機比它高的時候維持現高。
2. **直線**飛回起飛點。
3. 在起飛點上方下降（`RTL_ALT_FINAL_M`；這台是 0 ＝直接降落）。

危險在第 2 步：**起飛點與現在位置之間隆起的地形，返航會直接撞上去**，
而規劃畫面從來沒有畫過那條線。

### 12.2 算什麼

對航線上**每一個取樣點**：返航巡航高度 ＝ `max(當下的規劃高度,
起飛點海拔 ＋ RTL_ALT_M)`，然後沿著「那一點 → 起飛點」的直線每 30 m 量一次
離地，取最小值。負的就是「從這裡失聯會撞地」。

* **沒讀到 `RTL_ALT_M` 就不判**，畫面寫「返航沒有檢查」——同 `wp_spd`
  的規矩：**讀不到不等於沒問題**。
* 路上有高度未知的建物 → `rtl_blind`，同樣不當成沒有障礙。
* 訊息要說出**這一項改的是機上參數，不是航線**：改航線不會讓返航變安全。

### 12.3 畫在哪

* **返航高度**是 AMSL，所以直接畫成剖面上一條虛線。它在稜線上會跟著航線、
  一進谷地就壓平到 `home + RTL_ALT_M`——那個形狀本身就把機制講清楚了。
* **餘裕不是這張圖的 Y**（返航飛的是另一個方向的地形），所以它畫成
  X 軸下面一條帶子：紅＝那條線會撞地、黃＝餘裕不足、灰＝沒事。
  硬畫成 Y 會讓人以為那是同一條剖面上的高度。

### 12.4 實測（場域西南 44 m 稜線）

起飛點地面 123 m、航點 111 m、中間 167 m。`RTL_ALT_M = 5`（這台機現在的值）：

> **從 seq 6 附近返航會撞地**：`RTL_ALT_M` 是 5 m（**離起飛點**，不是離地形），
> 返航會在 128 m 海拔直線飛回去，而那條線上最低只離地 **−40.7 m**。

62 個取樣點裡有 23 個是紅的。照訊息說的調到 48 m 才過得去。

**注意這條航線本身是通過的**（逐段都貼著地形 3 m）——會撞的是它的
失效處置。這正是 C7 的意思。

## 13. 場域資料包（2026-09-09）

使用者：「做這個未來會用 API 的方式傳給其他系統，讓它可以即時呈現畫面。」
**那句話改變了形狀**：不是打一包 tar 帶去現場而已，是一份**別的系統讀得懂
的資料集**。

### 13.1 caveat 是介面的一部分，不是文件

拿到一堆 PNG 的人不知道那是 terrarium 編碼、不知道地面線畫不出任何一棟樓、
不知道八成建物的高度是猜的。**所以 manifest 裡每一種來源都帶 `caveat`。**
沒有它，接收端會把一份 30 m 格子的表面當成地形圖用——那正是這個專案
一路在防的那件事，只是換到系統邊界上。

`buildings` 那一層還多給 `measured`／`unmeasured`／`unmeasured_pct`
（本場域 59 棟、50 棟沒量過、85%）：接收端要拿它決定那些樓在畫面上該長
什麼樣子，那是它的判斷，但**它得先知道有這回事**。

### 13.2 圖磚不複製

`data/bundles/<name>/` 裡只有 `manifest.json` 與 `buildings.geojson`。
圖磚留在共用快取（`data/terrain-tiles`、`data/ortho`），manifest 指的是
既有的端點；`archive.tar` 是打包那一刻才從快取抓出來串流的。

複製一份進資料包只會讓同一張圖磚在磁碟上有兩份，而且會過期。

### 13.3 東西在哪

| | |
|---|---|
| 枚舉／manifest／涵蓋率 | `libs/bundle.py`（純計算，現場沒網路也能跑） |
| 打包 | `scripts/pack-field.py`（會上網——所以**不長在 libs 裡**） |
| 清單／manifest／建物／整包 | `GET /api/bundles`、`/api/bundles/{name}`、`/{name}/buildings.geojson`、`/{name}/archive.tar` |
| 回歸 | `scripts/test-bundle.py` |

`--no-fetch` 是**現場模式**：只數不抓，回答「我手上這一份夠不夠飛這個場域」。

### 13.4 實測

`itri` 半徑 800 m：地形 z10–15 共 16 張 / 0.6 MB，正射 z14–18 共 231 張 /
5.8 MB，建物 59 棟。`archive.tar` 249 個檔、6.85 MB。

名稱會被接進路徑，所以擋掉 `/`、`\`、開頭的 `.`——編碼過的穿越也試過，
`%2e%2e%2f` 走不進去。

## 14. 圍欄（2026-09-09，使用者裁定：圓形＋多邊形，只做規劃端）

### 14.1 兩種圍欄不是同一件事

| | 畫在這一頁的 | 飛控裡的 |
|---|---|---|
| 住在哪 | `plans.fence`（跟著這份航線走） | `FENCE_*` 參數 ＋ 圍欄任務 |
| 什麼時候作用 | **上傳之前**（`check_fence`） | 飛行中，會讓飛機停下來 |
| 現在有嗎 | 有 | **沒有**（`N` 排下一步） |

**畫面必須寫「飛控不擋」。** 畫一個圈很容易被讀成「飛機不會飛出去」，
而現在飛機會——這是這一版最容易致命的誤讀，所以那顆紅晶片跟著圍欄晶片走，
剖面圖上那條上限線也把同一句話寫在標籤裡。

### 14.2 兩種形狀

* **圓形**：圓心固定是**起飛點**。一個數字就講完，而且對得上飛控的
  `FENCE_RADIUS`（那顆也是以 home 為心）——做 N 的時候不用改形狀。
* **多邊形**：點地圖加頂點。貼合真實場地，但**要飛機真的擋就得上傳圍欄
  任務**，那是 N 的題目。

兩者都可以帶**高度上限**，語意與 `FENCE_ALT_MAX` 一樣：**離起飛點**。
地形跟隨（frame 10）的航點高度不是離起飛點的，比不了——那時報的是
「比不了」，不是「通過」。

### 14.3 匯進來的圍欄不會被畫面蓋掉

QGC 的 `.plan` 可以帶排除區與多個形狀，這一頁的編輯器畫不出來。所以
`editable()` 判定「這一頁能不能代表它」——不能就不送 `fence` 上去，
資料庫裡那份原封不動。

### 14.4 東西在哪

| | |
|---|---|
| 建圍欄／判定 | `libs/plan_check.py`：`fence_circle`、`fence_polygon`、`check_fence` |
| API | `POST /api/plans/draft`、`POST /api/plans/{id}/preview` 的 `fence`；`GET /api/plans/{id}/profile` 回 `fence` |
| 畫面 | 規劃頁的圍欄列、表頭晶片、`TerrainStage` 的 `fence-*` 圖層、剖面圖的上限線 |
| 回歸 | `scripts/test-plan-policy.py` |

## 15. 三件關於「畫線當下」的事（2026-09-09）

### 15.1 拖曳要當場動

點的位置原本只從剖面回來——拖曳時每一步都要跑一趟後端（去抖 220 ms
＋沿線取樣 DEM），**放開滑鼠之前畫面完全不動**，看起來像卡住。

現在**操作員放的點直接讀 `pts`**，不等後端：`stageWps` 上有 `srcI` 的點，
位置一律取自操作員那一份。系統補的中繼點沒有 `srcI`，它們本來就要重算
才知道在哪——那個延遲是真的，不該假裝。

### 15.2 `src_i`：航點記得自己是操作員的第幾個點

原本畫面用**位置**去數（`stageWps` 的第 i 個 ＝ 第 i−1 個操作員點）。
中繼點也在那個序列裡，所以只要補過點，拖 A 會改到 B，而且中繼點越多
錯得越遠；降落點更是永遠對不上——它在序列尾巴，數過去早就超出範圍，
於是**降落點拖不動**。

`build_plan` 現在把來源索引寫進航點（`src_i`），`route_profile` 帶出去，
畫面認它：拖曳、改高度、改類型、刪除都走同一個索引。

### 15.3 不預設飛回起飛點

`default_policy()` 的 `land_at_home` 改成 **False**。畫線的時候憑空多一條
回到原點的線，讀起來像自己畫錯了——而那條線是系統加的。沒有標降落點時
就降在最後一個航點；要回起飛點是**選出來的**（把某個點標成降落點，
再選「起飛點」）。

## 16. 地址定位、起飛點、飛控圍欄（2026-09-11，裁定：B／P／越界返航／多邊形一起做）

原型：`doc/geocode-fcfence-proto.html`。

### 16.1 從地址開始

使用者不會記得經緯度。工具列的「地址、地標或座標」一格取代原本的兩格座標：

* **查不到門牌就往上退一層，並說出退到哪**（號 → 巷弄 → 段 → 路），
  每一筆結果標精度（門牌／路段／地標／行政區）。OSM 的台灣門牌很稀疏，
  精準到門牌的 TGOS 要申請——PoC 先不問。
* 貼座標或 Google Maps 連結直接跳過去，**不上網**；座標還可以「設為起飛點」。
* 地址查詢送到外部服務（OSM Nominatim），一秒一次，所以按 Enter 才查。
  **現場沒網路時查不了**，座標照樣能用。
* 選了結果只是把地圖移過去（`TerrainStage` 的 `flyTo`，只在它變的時候飛）
  ——**起飛點還是自己點**。

### 16.2 起飛點拖得動、刪得掉

從零畫的時候起飛點由使用者決定，所以不再 `fixed`；拖曳時位置直接讀
`home`，不等後端。刪除後回到「放起飛點」，航點留著。既有航線的起飛點照舊固定。

### 16.3 圍欄跟著上傳寫進飛控

**航線跟飛控裡的圍欄是同一份。** `mission_upload` 在所有閘門之後、傳航線之前：

1. 讀 `FC_FENCE_READ`（沒有的名字安靜缺席：舊韌體沒有 `FENCE_ALT_MAX_TP`、
   `RTL_ALT` 是 cm）
2. `plan_check.fc_fence_plan` 算出要寫的東西；有 problems 就整次不上傳
3. 關 `FENCE_ENABLE` → 寫 `FENCE_TYPE`／`FENCE_ACTION=1`／`FENCE_ALT_MAX`
   （逐個讀回，被夾就算失敗）→ 傳圍欄任務（逐項讀回，含 param1）→ **最後才開**
4. 任何一步沒過：圍欄停在關著，航線不傳，訊息說出做到哪一步

**形狀一律走圍欄任務，圓也是。** 原型寫的是 `FENCE_RADIUS`，實作時改掉：
那個圓以**解鎖的位置**為心，飛機在離規劃起飛點 50 m 的地方解鎖，圈就跟著
移 50 m——而規劃頁檢查的是以規劃起飛點為心的那一個。圍欄任務裡的圓有
自己的圓心，寫進去的就是檢查過的那一個。所以 `FENCE_TYPE` 是 1（高度）|4
（圍欄任務），不開 2。

不寫的條件：返航高度讀不到、或不低於圍欄上限（越界之後的返航本身會再越界）；
`FENCE_ALT_MAX_TP` 存在而不是 1（上限不是離起飛點算的）。

**航線沒有圍欄時，把飛控的圍欄關掉**（`FENCE_ENABLE=0`，讀回確認；本來就關著
就不寫）。原型建議的是不動——怕關掉別人為場地設的保護——使用者改選這一個：
不動的話，傳過一次帶圍欄的航線之後圍欄就一直開著，而有圓或多邊形的圍欄開著時
飛控要有定位才肯解鎖，室內測試得另外手動改參數。**關不掉就不傳**：飛機不該
帶著上一份航線的圍欄去飛這一份。代價照實記著：用 QGC 另外設的圍欄，傳一份
沒畫圍欄的航線就會被關掉。

不是 ArduPilot 的機不寫也不關，結果裡說出來。

### 16.4 圍欄頂點可以選、拖、刪

跟航點同一套手勢：點一下選中（右欄顯示第幾個頂點與座標，有「刪除這個頂點」），
按住拖曳只移動位置。頂點畫在 maplibre 的圖層上、不在 three.js 那一層，所以
命中用 `queryRenderedFeatures`；**頂點優先於航點**。刪到不到三點時晶片寫
「還不成立」——那時後端視為沒有圍欄。

**加頂點插進讓周長增加最少的那條邊**，不是一律接在最後——照點擊順序接，
點的順序一亂圈就交叉；也不用凸包，場地不是凸的。兩點時就畫出一條線。
拖頂點仍然可能拖出交叉，所以 `plan_check.fence_crossing` 會在規劃頁報出來，
交叉的圍欄也不會寫進飛控。

**點位分開編輯。** 「編輯圍欄」按下去時只有圍欄頂點能選、能拖，航線變淡、
點不到；放開時反過來，頂點變淡、點不到。兩種點不會因為疊在一起而動錯。

### 16.5 人工審查也綁圍欄

`plan_checks.fence_hash`。圍欄改了那份審查就失效；指紋取正規形，改回原本的
圍欄審查就又算數。沒有圍欄的航線兩邊都是 None，舊的審查不受影響。

### 16.6 驗到哪裡

* ArduCopter SITL（`radarku/ardupilot-sitl`，舊版韌體）：多邊形 4 點、換成圓，
  參數與圍欄任務逐項讀回一致、ENABLE 最後打開；之後傳航線任務，圍欄任務還在。
  **走的是實際的 `mav.py`**，不是另寫一份協定。
* 圍欄任務在開關 `FENCE_ENABLE`、等待、重新連線之後都還在。唯一一次例外：
  第一輪留下的圓，第二輪連上時讀到 0 項——重做那幾個動作都沒有再出現，原因不明。
* 上傳端點本身沒在 SITL 上打過：入列要求機上代理，模擬器沒有。
* **真機（4.7）還沒驗**：兩台機都離線。第一次上真機要看 `FENCE_ALT_MAX_TP`
  讀到的是不是 1，以及室內有圍欄時解鎖會被 GPS 前置檢查擋下。
