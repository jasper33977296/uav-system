# uav-agent 從零安裝、一鍵部署：重新設計

> 狀態：**提案**（2026-10-19）。使用者要求：「根據今天遇到的問題，從 0 開始設計 uav-agent
> 從零開始安裝、一鍵部署好」。每一節實作前逐節核可。
>
> 範圍：**從一張空白 SD 卡，到一台會飛、會量 5G、地面站看得到的無人機**。
> 代理本身的行為（意圖協定、入列、三層防線、076 綁定）不在這份重新設計的範圍內，
> 只列出安裝流程需要代理配合的地方（§9）。
>
> 現行實作：`deploy.sh`＋`install-service.sh`＋`tools/env-wizard.py`＋`tools/dongle-check.py`
> （uav-agent 20c7bdc 起）。2026-10-19 用它從空機裝好 drone E，但過程中停了兩次、
> 靠人工查了好幾件事——這份設計要把那些都收進流程裡。

---

## 0. 目標

```bash
./uavctl install            # 一個指令。插好 SD 卡的空 Pi、接好飛控與 dongle、上電
```

結束時只有兩種結果：

- **✓ 裝好了**，附一張「量到的」證明：飛控身分、鮑率、sysid、5G 訊號、到地面站雙向通、對時、
  地面站入列成功而且是新的一筆。
- **✗ 停在第 N 步**，說清楚卡在哪、機上改了什麼、下一步人要做什麼。

中間**只問人兩種問題**：只有人知道的（密碼、這台叫什麼），以及要人做決定的（別人的服務佔著
飛控埠要不要停）。其他一律量出來給人確認。

## 2. 前置：地面站自己先要是好的

`uavctl` 在**地面站上**跑（現在的開發機就是地面站）。第一件事檢查自己，因為今天 14:32 之後
無論機上裝得多好都連不到——地面站的 5G 網卡被 NetworkManager 搶走了設定。

| 檢查 | 不過的話 |
|---|---|
| 地面站服務都在跑（backend、command、DB） | 停，說是哪個 |
| **地面站的 5G 網卡**（以 Fibocom USB 路徑指認）有 IPv4 | 停：「地面站 5G 網卡沒有 IP」，並指出是哪個 NM 設定檔把它搶走 |
| NM 的每個有線設定檔都綁了網卡 | 警告＋提供一鍵修正（這次 14:32 的根因） |
| NTP 服務在跑 | 停 |

## 3. 第零步：燒錄（讓「未知」在開始前就消失）

今天前一個半小時花在「它在哪、帳號是什麼」。這兩件事在燒錄時就能決定，所以流程從燒錄開始：

```bash
./uavctl image --name drone-f --sd /dev/sdX     # 或產生給 Raspberry Pi Imager 用的設定
```

- 支援一種作業系統：**Raspberry Pi OS Lite（64-bit）**。現有的 Ubuntu 機（drone E）以 §5 的 OS
  介面卡相容，但新機一律用這一種——每多支援一種 OS，§5 就多一套要維護的分支（待決 §10-1）。
- 寫進 firstrun／cloud-init：
  - 帳號 `uav`、**只放地面站的 SSH 公鑰**（不設可登入的密碼 → 不必再猜、也不會被猜）
  - hostname＝`drone-f`
  - 開機在乙太網與 5G 上都**廣播自己**（mDNS `drone-f.local`＋§7 的 UDP 宣告）
- 產生 `drone-f.env`（不含密碼，因為不需要了），記下這台的名字與燒錄時間。

**已經燒好、不是用這個工具燒的機**（例如 drone E）：走 §4.1 的「找＋問密碼」路徑，跟今天一樣。

## 4. 第一步：discover（只讀）

**保證**：這一步結束時，機上一個位元都沒變——包括 `authorized_keys`。用密碼登入時用
`SSH_ASKPASS`，不跑 `ssh-copy-id`。

### 4.1 找到這台機

依序試，第一個成功的就用：

1. `drone-f.env` 裡記的位址
2. mDNS `drone-f.local`
3. §7 的 UDP 宣告（機上開機就會送）
4. 地面站各網卡的 IPv6 鄰居裡、網卡 OUI 是樹莓派的（今天 drone E 就是這樣找到的）

**已經在跑代理的機**（地面站學到的對端）永遠排最後並標警告，Enter 不會選到它。

### 4.2 量這台機

一次 SSH 帶一支只用標準函式庫的探測程式（今天的 `dongle-check`＋精靈探測合併），回傳一份 JSON：

| 項目 | 怎麼量 |
|---|---|
| OS、版本、網路管理者 | `/etc/os-release`；NetworkManager／networkd 誰在跑 |
| Python 版本、架構 | 決定 §6 要帶哪一包 |
| 飛控序列埠、鮑率、出廠 sysid、板號 | 候選鮑率各聽 2.5 秒，連續訊框＋compid 1；能的話問一次 `AUTOPILOT_VERSION` |
| dongle | USB `2cb7:0105`，不是 `01fd`（mass-storage） |
| AT 埠 | dongle 底下、回 OK 的；**以 USB 介面路徑記**（`4-1:1.1`），不記 `ttyUSB1` |
| 5G 網卡 | dongle 底下的 net 裝置，**以 USB 路徑記**；有沒有 IP；dongle 自己有沒有撥上（`AT+GTRNDIS?`）——今天 drone E 是「dongle 撥上了、網卡沒開」，兩者都要量才分得出來 |
| 到地面站 | 從 5G 網卡 ping 地面站 |
| 誰佔著飛控埠、AT 埠 | `/proc/*/fd`；對到 systemd unit 名 |
| 供電 | `usb_max_current_enable`、`get_throttled`、開機以來 dongle 重新列舉幾次 |
| 時鐘 | 有沒有對過、偏差多少 |
| 是否已裝過代理、哪個版本、綁定哪塊板 | 決定是 install 還是 deploy |

### 4.3 給人確認

一張表，量到的值附「怎麼量到的」，Enter 接受或改。要人決定的另外列：

```
  需要你決定
  ─ 飛控埠被 sdr-fc-telemetry.service（k200）開著。代理跑的期間會封鎖並停掉它（§10-2），
    代理停了才放回。  [Enter] 知道了  [n] 取消安裝
  ─ 這次沒聽到飛控。 [1] 飛控還沒接，先裝其他的（驗收時飛控標「…」）  [2] 取消
```

確認後寫出這台機的**宣告檔** `machines/drone-f.json`（§7）。

## 5. 第二步：apply（宣告式、可重跑）

每一項都是同一個形狀：**讀現況 → 跟宣告比 → 只改不同的 → 記錄改了什麼**。沒有「假設某個檔案存在」
（今天的 unit 備份）、沒有「每次都重寫」（今天的對時 drop-in）。

| 項目 | Pi OS（NetworkManager） | Ubuntu（networkd） |
|---|---|---|
| SSH 金鑰、免密碼 sudo | **從這一步才裝** | 同 |
| 執行帳號 | 宣告檔指定；服務以它執行（drop-in） | 同 |
| 排針 UART | `config.txt` 加 `dtoverlay=uart0-pi5` | 同 |
| USB 供電上限 | `config.txt` 加 `usb_max_current_enable=1` | 同 |
| 日誌持久化 | drop-in 蓋過 `40-rpi-volatile-storage.conf` | 預設已是 persistent，確認即可 |
| dongle 網卡 | NM 預設會 DHCP，確認即可 | netplan：以驅動 `cdc_ether` 比對、DHCP、route-metric 700 |
| ModemManager | 停用 | 停用 |
| 飛控埠的其他佔用者 | 依 §4.3 人的決定 | 同 |
| 對時 | timesyncd 只對地面站；清掉其他 drop-in | 同 |
| 代理目錄與錄製目錄 | `/opt/uav-agent`、`/var/lib/uav-agent`、`/opt/uav-record`，擁有者＝執行帳號 | 同 |
| 服務 | 共用 unit（**不放任何參數**）＋帳號 drop-in；開機自啟 | 同 |

需要重開機的項目（`config.txt`）**全部做完後統一重開一次**，等它回來（用 §4.1 的方式重新找，因為
5G 的 IP 是 DHCP、可能換了），再重跑 §4.2 確認重開後硬體都還在。

## 6. 第三步：放上代理（版本包）

- 地面站上產出版本包：`uav-agent-<commit>-py3.12-aarch64.tar`＝程式＋對應 Python 版本與架構的
  wheel（今天驗證過可行：6 個 wheel，機上不必連網）。
- 不靠 `python3-venv`：包裡帶 `pip` wheel，用 `python3 -m venv --without-pip` 起 venv。
- 機上：`/opt/uav-agent/releases/<commit>/`，`current` 是 symlink。
  **切版本＝換 symlink＋重啟**；回滾是換回 symlink，不是 rsync 回去。保留最近 5 版。
- 解鎖中不准切換（沿用）。閘門讀代理自己回報的**單調年齡**，不讀檔案 mtime——今天 Pi 開機時鐘
  跳了 80 分鐘，mtime 判成「4845 秒沒更新」。

## 7. 設定住所

| 層 | 住所 | 內容 | 誰寫 |
|---|---|---|---|
| 共用 | 程式碼、unit | 行為參數；unit 只有路徑與權限 | 開發者 |
| 場域 | 地面站 `site.json` | 地面站 ID、地面站位址 | 地面站自己 |
| 這台機 | 地面站 `machines/<name>.json`（宣告）→ 機上 `/var/lib/uav-agent/machine.json` | §4.2 量到並確認的一切 | `uavctl`，人確認 |
| 密碼 | 不存（§3 之後就不需要）；舊機暫存在 `drone-*.env`（gitignored） | | 人 |

**地面站位址不再是設定**：地面站每 5 秒在已知 UDP 埠向 5G 網段宣告
`{"gcs": "<site id>", "ip": "<自己 5G 網卡的 IP>"}`。代理先用記住的位址；連不上時聽宣告，**只認同一個
site id 的**，找到新位址就記下並發 `notice`。今天這種「地面站換 IP → 改 unit → 重新部署每一台」
的流程消失。對時伺服器跟著它走（一個事實一個住所）。

## 8. 第四步：prove（量到才算裝好）

每一項是一個**量測**，不是「設定寫進去了」：

| 檢查 | 怎麼量 | 硬條件 |
|---|---|---|
| 版本 | 代理狀態列的 `deployed` | ✓ |
| 飛控 | 心跳、`AUTOPILOT_VERSION` 板號、身分 `ok` | ✓（§4.3 人明說沒接飛控時可為「…」） |
| 飛控埠獨佔 | 狀態列 `port_holders` 為空 | ✓（人選了保留時標「有共用者」） |
| 5G 網卡 | 有 IP，而且就是 §4.2 量到的那張 | ✓ |
| 5G 取樣 | 代理取樣數 > 0、RSRP／SINR 有值 | ✓ |
| 到地面站 | 意圖通道連上、遙測收得到（**地面站那頭量**，不是機上自己說） | ✓ |
| 對時 | `NTPSynchronized=yes`、偏差 < 100 ms | ✓ |
| 入列 | 地面站 `/api/admission/<sysid>` 是 `admitted`，**board_uid 是這塊板、跟其他機不是同一筆** | ✓ |
| 重開機存活 | （`--reboot-test`）重開一次後以上全部再過一次 | 選用 |

輸出一張報告存在地面站 `machines/<name>.install-<時間>.json`，下次 `uavctl status` 拿它比。

失敗時：**不回滾**（保留現場），印出已經改了的項目清單（§5 的紀錄）與下一步建議。

## 9. 代理本身要配合的（最小集合）

1. **流量綁 5G 網卡**（`SO_BINDTODEVICE`，以 USB 路徑找到的那張）。乙太網、Wi-Fi、mesh 的路由
   怎麼設都帶不走遙測；今天 drone E 接乙太網時的掉包，至少不會影響代理。
2. **讀 `machine.json`**：鮑率、sysid、AT 埠（USB 路徑 → 當下的 ttyUSB）、5G 網卡。開機重驗，
   驗不過重新偵測並發 `notice`（「飛控鮑率從 57600 變成 115200」）；不自動改綁定身分。
3. **狀態列報 `health`**：每個子系統 `ok／degraded／unknown`＋年齡＋原因。`unknown` 不准當 ok。
   prove 與前端都讀它，不各自推斷。
4. **聽地面站宣告**（§7）。

## 10. 使用者裁定（2026-10-19）與仍待決

**已裁定**：

1. **「我不能控制 UAV 的環境，所以要相容。」** 不重刷、不要求特定作業系統或帳號。§3 的燒錄工具
   降為**選用**（自己燒的機才有），§4 的「找＋問密碼」與 §5 的 OS 介面卡是主路徑。
   ⇒ 已實作：帳號不限 `pi`（drop-in 改 `User=`）、Ubuntu／networkd 的 dongle 網卡、ModemManager。
2. **「起碼在 agent 運行時要完全佔用。」** 代理要用的序列埠（飛控、AT）在代理跑的期間只屬於它。
   ⇒ 已實作（uav-agent `f83a480`，`systemd/claim-ports.sh`）：啟動前把開著這些埠的**系統服務**
   `mask --runtime`＋stop（Restart= 拉不回來），其他行程 TERM→KILL；代理停了解除封鎖、不主動拉起。
   drone E 的 `sdr-fc-telemetry.service` 就是這樣被擋下的——在這之前它在代理重啟時搶先重開飛控埠並
   上獨佔鎖，代理開不回來（EBUSY）。§4.3 的「保留共用者」選項因此**拿掉**。
3. **宣告檔不進 repo。** `machines/*.json` 只留在地面站本機。
4. **安裝完程式只留在 `/opt`，安裝來源整個刪掉。** 在 Pi 上 pull 下來直接跑（本機模式）時，
   成功後刪除那個資料夾（裡面的 `drone-*.env`／`machine.env` 含密碼，一起刪）；安裝暫存 `.wheels`
   兩種模式都刪。⇒ 已實作（`1e59b23`），drone E 上實測過。

**仍待決**：

5. **乙太網掉包的根因**仍未查到；§9-1 讓代理不受影響，但不等於知道原因。
6. **兩台都出廠 sysid 1**：入列配號（040）還沒在真機上同時跑過兩台。
