# 實體驗證清單（首飛前）

> **用途**：目前系統的能力宣告**幾乎全部只有 SITL 證據**。這份清單列出每一項
> 「在模擬器上驗過、但在真機上沒驗過」的東西，以及**不驗的話會怎樣**。
>
> 對象：要把這台機第一次飛起來的人。
>
> **要填的表在 [`verification-checklist.md`](verification-checklist.md)**——
> 這一份講的是每一項「為什麼要驗」與「不驗會怎樣」，那一份是現場拿著填的。
> 分開的理由：現場需要的是一張能填的表，不是一篇要讀的文章；而理由不能刪，
> 少了它，日後有人會把某一項當成形式主義跳過。
>
> 相關：[`deploy-checklist.md`](deploy-checklist.md)（部署前設定）、
> [`autonomous-flight-state-machine.md`](autonomous-flight-state-machine.md)（狀態機設計）。

## 查核表怎麼用

**每一項填四格：日期／韌體版本／結果／證據。** 只打勾不填版本等於沒驗——
今天的教訓：`data/conformance/*.json` 原本宣稱記錄韌體版本，而那個欄位根本
不存在，於是「對某版驗過」這句話說不出後半段；補上之後才發現 ArduPilot SITL
是 4.0.3，**而那個差距改變了一個設計結論**。

結果只有三種，**沒有「大概可以」**：

| 記法 | 意思 |
|---|---|
| `PASS` | 判準那一欄寫的，親眼看到了 |
| `FAIL` | 沒看到，或看到別的。**照失敗處置那欄做** |
| `SKIP` | 沒測。**skip ≠ pass**——沒測就是沒有證據，不得往下走 |

「證據」欄要能讓別人重看：截圖檔名、`data/conformance/*.json` 的檔名、
tlog 時間戳、或 `journalctl` 的那幾行。**寫「看起來正常」不算證據。**

## 0. 為什麼需要這份清單：證據強度的落差

| 項目 | 目前的證據 | 落差 |
|---|---|---|
| 任務執行（`mission_start`／`mission_fly`） | ArduPilot **4.0.3** SITL | 機上是 **4.7.0**，差 7 個 minor |
| 續飛（`MISSION_SET_CURRENT`） | 同上 | 同上 |
| 起飛序列、模式切換 | 4.0.3 SITL ＋ 2026-08-12 一次實飛 | 部分有真機證據 |
| 5G 訊號欄位對照 | **FM350 手冊**推導 | 機上是 **FM160**，同家族但非同型 |
| 板子 UID 的穩定性 | 單次讀取 | **跨重開機／韌體升級沒驗過** |
| 幾何圍欄值 | `.env` 未設 → 程式預設 **50m / 15m** | 那是**模擬環境**的值 |

**SITL 用的映像 `radarku/ardupilot-sitl` 已經五年。** 今天實測就出現過一次
版本相關的行為差異（指令 224 不支援），所以「SITL 過了」與「真機可用」之間
的距離是實際存在的，不是形式上的免責聲明。

## 2. 需要起飛才能驗

> **依序做，前一項沒 PASS 不做下一項。**
> **每一項都要有人在遙控器旁邊、能隨時接管。**
> 場地圍欄值先依實際場地重設——`.env` 現在是模擬用的 50m/15m。

| # | 查核項 | 判準 | 失敗處置 | 日期 | 韌體 | 結果 | 證據 |
|---|---|---|---|---|---|---|---|
| **2.1** | 解鎖與起飛 | `mission/fly` 到 15 m 並停住；讀回高度在 ±2 m 內、模式為 GUIDED/AUTO | 立刻接管降落。查 `takeoff_plan` 的高度語意（相對 vs 海拔） | | | | |
| **2.2** | 單點任務 | 兩點短航線能進 AUTO 並飛完，`mission_seq` 依序遞增 | 接管返航。查 1.3 的索引換算 | | | | |
| **2.3** | 中止 | 飛行中 `mode/hold` → **讀回 `mode_verb == hold`**（不是看 ACK） | 接管。這是三步序列的第一步，不成立則 2.6 不能做 | | | | |
| **2.4** | 返航 | `mode/rtl` → 自主返航、降落、上鎖 | 接管降落 | | | | |
