## 設計判準（唯一一條）

畫面上每個元素都要過這關：**一個沒讀過任何說明的人，第一眼知道這是
什麼嗎？** 不知道 → 換成直覺符號，或從預設畫面移除（收進展開處，不刪）。

```
┌─────────────────────────────────────────────┐
│ ◉                                    ▤  ⚙  │ ← 左上機隊點（每機一色點）、右上兩個 icon
│                                             │
│                                             │
│                （全幅地圖＋航跡）              │
│                                             │
│                                             │
│              ⚠ 訊號變差了                    │ ← 只在異常時浮現的一句人話，解除即消失
│                                             │
│  ▲32m   →5.0   ▮▮▮▯  🔋81%          （▶）  │ ← 底部一列：icon＋數字，零標籤字
│  ────────────────────────────────────  ↑    │
│  ⓘ 14:32 訊號瀕斷                    主按鈕  │ ← 最新一條事件單行，上滑展開完整 log
└─────────────────────────────────────────────┘
```

### 具體規則

1. **零標籤**：現在的「相對高度 29.0m」「電量 81%」「GPS 3D·10」「PX4」
   「就緒」「MISSION」徽章全部從預設畫面移除。高度＝`▲32m`、速度＝`→5.0`、
   電量＝電池圖形（圖形本身顯示存量）、訊號＝手機訊號格（格數＝分級，
   顏色只是輔助）。人類已經被手機訓練過這些符號，不需要教。
2. **零解釋文字**：deadman 說明、串流指引、ENABLE_COMMANDS 教學——
   預設畫面一個字都不出現。唯二有文字的地方：**事件 log**（人話句式）
   與**異常浮出句**（「失去連線——機體自動懸停中」）。
3. **狀態只在變化時說話**：一切正常時，畫面上沒有「就緒」「連線中」
   這類字——正常是預設，不需要宣告。異常才浮出一句話，且說**發生了
   什麼＋機器正在做什麼**，不說術語（不出現 deadman/Hold/failsafe 字樣）。
4. **一顆主按鈕**：情境決定它是「起飛」還是「返航」。其餘操作（任務
   上傳、手動、降落）收進主按鈕旁的展開。**安全機制原樣保留**：
   兩段式確認改為按鈕本體變色＋文字換「確定？」（機制不變、包裝直覺化）；
   緊急單擊不變。
5. **專業數值降級為抽屜**：SINR dB、RSRP/RSRQ/PCI、GPS 顆數、模式名、
   sysid——右上 ⚙ 或訊號格點開才出現。**不刪除，只隱藏**。
6. **事件 log 是唯一的文字區**：維持人話句式與 severity 底色，
   預設只露最新一條，上滑展開。

## 單一住所規則（使用者 2026-08-11 第五輪反饋：重複與重疊）

先鋒版病因：新 HUD 上線但舊元件未同步移除，同一資訊多處出現＋圖形
重疊。規則：**每個資訊在頁面上只有一個家**。名稱修正：「鏈路品質」
全站改為「**訊號品質**」。

| 資訊 | 唯一的家 | 因此移除 |
|---|---|---|
| 目前訊號 | HUD 訊號格；**點開**＝訊號品質面板（SINR 數值＋走勢＋5G 專業欄＋軌跡顏色圖例） | 地圖上常駐的圖例卡（併入面板）；抽屜裡的訊號卡 |
| 高度/速度/電量 | HUD 三格 | 抽屜側欄「飛行狀態」卡的同三項 |
| 事件 | 底部單行＋上滑 log | 抽屜裡的事件卡 |
| 模式/就緒 | 不常駐——異常浮出句涵蓋；查詢走抽屜「詳細」 | 任何常駐模式字樣 |
| 抽屜 ▤ 重定義 | 只放專業面板：GPS/姿態/5G 詳細（不重複 HUD 已有的任何數字） | 舊側欄三卡整套照搬 |

**擺位衝突規則**：左下＝HUD 專屬層（比例尺、座標、MapLibre attribution
全部讓位——attribution 縮最小移 HUD 上方，比例尺/座標移右下主按鈕
上方）；任何新元素不得與既有錨點重疊。**驗收條件補強**：帶滿航跡
＋1366×768 小視窗各驗一輪（本次重疊在大視窗空場景下漏抓的教訓）。

先前定案「操作者即研究者，5G 欄位是研究對象不能只靠摺疊」（ia-direction
定案 2）與本次「新手直覺、零標籤」直接衝突。本提案的立場：**簡約為
預設，研究數值全部存在但都在一次點擊之後**（訊號格點開＝完整 5G 面板，
含展開記憶）。若研究情境需要常駐數值，用「展開後記憶」達成，不回到
預設滿版。請 PM 確認此立場或改裁。
