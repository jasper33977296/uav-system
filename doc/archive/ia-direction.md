# 資訊架構方向：資訊該用什麼形式呈現（回應使用者不滿 6）

- 狀態：**已定案，可全面動工**（PM 2026-08-11 三題定案，見文末）
- 範圍：跨頁面的資訊呈現原則；各頁具體改動在核可後的分頁 restyle 稿

## 核心原則：形式跟著操作者的問題走

每個資訊依「操作者拿它回答什麼問題」歸入三類，全站一致：

| 問題 | 形式 | 例 |
|---|---|---|
| 「現在是多少？」（要讀精確值） | **數字**（tabular-nums） | SINR dB、高度、地速、電量%、RTT |
| 「現在正不正常？」（只判斷狀態） | **徽章/圓點＋文字標籤** | 連線、就緒、記錄中、鏈路分級、模式、機型 |
| 「怎麼變的？」（看趨勢） | **圖表** | SINR/RTT 走勢、回放時序 |

**判準**：一個數字如果操作者只拿來判斷「正常與否」，就降級為徽章，
精確值收進 tooltip。例：衛星數「10 顆」沒人在讀數值，讀的是「GPS 夠不夠
好」→ 改為 GPS 徽章（3D Fix·10）；反之 SINR 是研究對象，數字保留為 hero。

## 三條配套規則

1. **一卡片一問題**：飛行狀態卡回答「機的姿態與位置」、訊號卡回答
   「鏈路健康與趨勢」、事件流回答「剛剛發生了什麼」。卡片內不混問題——
   現況「飛行狀態卡」裡混了模式（狀態）與姿態角（數字）就是要拆的例子。
2. **同一資訊全站同形式**：模式名永遠是 chip（即時頁、回放頁、比較頁
   同款）；SINR 永遠是數字＋分級標籤並列。操作者學一次就通用。
3. **層級固定三層**：徽章列（狀態總覽，掃一眼）→ 主數字（當下值）→
   圖表（趨勢）。側欄卡片都照這個順序排，視線動線一致。

## 各頁影響預告（核可後分頁出稿）

- **即時頁**（重點）：側欄依三層重排；5G 細節（PCI/頻帶/CQI/SA）收進
  摺疊——它們是「查問題時才看」的資訊，不是常駐監看項。
- **/drones**：卡片頭＝徽章列（機型/連線/主機），統計數字歸網格。
- **回放/比較**：工具列的篩選/顯示控制統一成 chip 群；姿態角等
  「查問題資訊」進 tooltip 不佔版面。
- **事件流**（跨頁）：detail JSON 直出改人話模板（frontend.md 待做 2 的
  正式化），狀態色點＋動詞開頭句，連續同類事件摺疊計數。

1. **三分法與降級判準核可**，三條配套（一卡片一問題、全站同形式、
   三層動線）一併核可。
2. ~~5G 細節摺疊可以，附兩個必做配套（操作者即研究者，5G 欄位是
   研究對象）~~ **→ 本項被使用者 2026-08-11 第二輪反饋推翻**（PM 裁決）：
   簡約為預設、研究數值**一律**收在一次點擊之後＋展開狀態記憶，
   「常駐可見」要求撤銷。保留兩個不佔版面的配套：a) 展開記憶；
   b) cell/PCI 變更進事件流（除錯保險，與簡約不衝突）。

   異常時才說一句人話——**正常狀態的介面應該安靜**。
3. **事件人話模板另開 issue**（018），排 restyle 主波之後；
   restyle 過程順手能改的簡單案例先改。
