# 前端設計

Next.js (App Router) + MapLibre GL + zustand。地圖為中心（map-centric）的監控介面。

## 頁面結構（2026-08-04 設計討論定案）

**四頁，不多了。** 頁面由「誰、什麼時候、在問什麼」推導，
且凡是 QGC 已經做得好的（飛行儀表、任務規劃）一律不重做：

| 路徑 | 情境 | 回答的問題 |
|---|---|---|
| `/` | 飛行中 | 鏈路如何？資料**有沒有在記**？預計 vs 實際路徑？ |
| `/drones` | 管理／飛行後 | 機隊（註冊/刪除）與各架次統計；點列進回放 |
| `/replay/[id]` | 飛行後 | SINR 空間分布與事件時序（研究核心頁）|
| `/missions` | 實驗準備 | 路徑庫：.plan 上傳／機上讀回／選一條疊到即時頁 |

（原設計的 `/scene` 場景頁已依「系統對干擾無先驗知識」的釐清移除。）
不設任務規劃頁——規劃仍由 QGC 負責，我們只管理與疊圖。導覽為頂欄 tab。

**3D 呈現**（2026-08-04 定案）：傾斜視角＋50m 地面網格＋起飛點錨定；
實際路徑＝**懸浮在飛行高度的彩色絲帶**（垂直起降段畫垂直彩柱），
地面留淡色投影；預計路徑＝窄灰絲帶＋地面虛線；回放頁加白色方向箭頭；
無人機本體＝three.js 正圓球體（以 drone_id 為鍵的多機結構）。

**QGC 不嵌入前端**：QGC 是 Qt 原生應用，技術上無法嵌進瀏覽器；
更重要的是「backend 對 MAVLink 只讀不寫」的安全邊界——控制介面與資料蒐集
介面刻意分屬兩個視窗。「包在系統下」的體驗改由三層達成：
啟動腳本並排定位視窗、`.plan` 疊圖＋MAVLink 狀態鏡像（只讀）、
UI 明示「控制權在 QGC」。詳見 [qgc-integration.md](qgc-integration.md)。

## 即時監控頁的三個關鍵設計

1. **記錄狀態放側欄最頂端**（#004 armed gate 的 UI 後果）：待機時系統
   刻意不入庫，操作員必須一眼分辨「⬤ 記錄中·架次 #N」vs「◯ 待機（不記錄）」，
   否則會發生「飛了半天以為有資料」的事故。
2. **失聯 ≠ link_lost，視覺語言分開**：`link_lost`（量到訊號差）→ 鏈路卡變紅，
   資料是新的、顏色說話；失聯（`link_age_s` 超過 3 秒）→ 整卡**變灰**＋
   「已失聯 N 秒」橫幅、marker 空心、尾跡停筆。
   原則：**過時的資料絕不能看起來像現在的資料**。
3. **飛行儀表縮成一行帶**（高度·速度·電量各一個數字）——QGC 有完整儀表，不重做。

## 回放頁（`/replay/[id]`）

時間軸**底部橫放**（定案）：地圖在上、SINR 與 RTT 兩張圖共用 X 軸上下堆疊
（不做雙 Y 軸）、scrubber 拖動 ↔ 地圖位置點同步、事件以三角標記釘在時間軸。
SINR 線用中性墨色＋淡門檻帶（5 / -2 dB 兩條參考線），**不分段變色**——
地圖軌跡已載了分級色，圖上重複是噪音。

```
│ 頂欄：UAV 監控 | 即時監控 · 無人機 · 任務        ● ● ◯ 狀態圓點 │ 48px

│  ・懸浮絲帶（依 SINR 四段上色）＋地面投影      │   28vw, 380px) │

│  ・地面網格 50m／起飛點錨定／圖例／比例尺      │ ・訊號品質卡    │
│                                             │ ・事件流（撐滿）│
└─────────────────────────────────────────────┴────────────────┘
```

縮放行為（都實測過）：側欄用 `clamp` 不寫死，視窗縮小／瀏覽器放大時按比例
讓出空間；≤860px 改上下堆疊（地圖 52% 在上、面板捲動在下）；shell 用
`100dvh`；sparkline 用 viewBox 而非固定 px；長模式名（RETURN_TO_LAUNCH）
可斷行；事件 detail 超寬以省略號截斷。

**WebSocket 掛在 AppShell（layout 層）**，換頁不斷線，連線／記錄狀態 chips
全站可見。「記錄中／待機（不記錄）」chip 的條件與 backend 入庫條件一致
（armed 且有架次，見 issues/004）——語意是「現在的資料有沒有被記下來」。

狀態圓點（後端／MAVLink／記錄中）縮為純圓點，語意放 title。

## 圖層的誠實原則（2026-08-04 釐清）

**系統對干擾無先驗知識。** 干擾區與 gNB 圖層已全面移除（模擬器照常在
該座標劣化 SINR，但畫面上只有量測結果，沒有假設標注）。地圖上只有：
預計任務路徑、依實測 SINR 上色的實際軌跡、起飛點、網格與比例尺。
沒有底圖也成立——路徑間的幾何關係是相對的，「場域的樣子」由彩色軌跡
自己累積揭露：那是研究產出物，不是輸入。

**視覺平滑邊界（2026-08-11 定案，issues/017）**：地圖上的路徑幾何可做
視覺平滑（spline／滑動平均），但研究圖表（回放時序、比較頁）一律用
原始樣本；顏色分級不插值——不得產生量測點之間的假 SINR 值。絲帶是
路徑的示意呈現，平滑只影響繪製、不改資料。

## 軌跡上色規則（研究主視覺）

鏈路健康是一種**狀態**編碼，用 status palette 四段，門檻與 backend 事件門檻一致
（`lib/signal.ts` 單一出處）：

| 分級 | SINR | 顏色 |
|---|---|---|
| 良好 | ≥ 13 dB | `#0ca30c` |
| 尚可 | 5–13 dB | `#fab219` |
| 劣化 | -2–5 dB | `#e05e0e` |
| 瀕斷 | < -2 dB | `#a01818` |

色值經 CVD 驗證選定（2026-08-04）：原「劣化」`#ec835a` 與「尚可」的 ΔE 僅
13.6，連正常色覺都難分，換 `#e05e0e` 後 ΔE 19+、色覺障礙模擬全過。
「尚可」的亮黃**不可改深**——其亮度是紅綠色盲分辨 良好↔尚可 的唯一線索。

配套規則：地圖左下常駐圖例；側欄同時顯示 SINR 數值與分級標籤（不靠顏色單獨傳達）；
面板文字一律用文字色，彩色只出現在狀態圓點與軌跡；
高密度軌跡點**不描邊**（描邊會蓋掉相鄰點的填色，實際踩過）。

## 即時資料流

- `lib/useTelemetry.ts`：WebSocket 連 backend `/ws/telemetry`，自動重連（2 秒）。
  **不經過 Next.js API route**，REST 也直連 FastAPI（CORS 已開）。
- `lib/store.ts`（zustand）：`live`（最新機況）、`trail`（尾跡，上限 1200 點）、
  `sinrHistory`（sparkline 用 120 筆）、`events`。
  地圖用 `subscribe` 直接更新 MapLibre source，不觸發 React re-render；
  側欄各自訂閱需要的欄位。

## 技術注意事項

- **MapLibre 依賴 `window`，必須關 SSR**：
  `dynamic(() => import("@/components/MapView"), { ssr: false })`，
  因此 `app/page.tsx` 是 client component。
- **底圖：預設深色畫布＋opt-in 影像/地形**（2026-08-11 修訂原 08-04
  無底圖定案，issues/017、doc/archive/3d-view-quality-proposal.md）：預設仍深色
  畫布（`#14181c`，離線保證＋對比基準）；使用者可切衛星/正射影像層與
  地形層，離線場域用預打包瓦片（部署手冊附錄的選配步驟），瓦片不可得時
  自動退回深色畫布並如實顯示。影像層開啟時加暗化 overlay 維持軌跡對比，
  狀態色盤需在影像背景重驗 CVD。**地形層在高度基準驗證通過前不對實場域
  開放**。無底圖時距離感只剩比例尺，ScaleControl 必開。
- 深色模式：CSS variables 在 `globals.css` 依 `prefers-color-scheme` 切換，
  色彩角色（surface/ink/hairline/series）皆為 light/dark 各自選定的值。
- 環境變數：`NEXT_PUBLIC_API_URL`、`NEXT_PUBLIC_WS_URL`（見 `.env.local.example`）。
