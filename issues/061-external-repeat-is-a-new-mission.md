# 061 · 外部控制重複執行同一條路徑，要算成不同的任務

- 狀態：open
- 嚴重度：medium（任務切分錯誤會讓多趟資料混在一起，比較就失去意義）
- 位置：`apps/command/app/main.py`（`mission_fly` 的任務編號）、
  `doc/external-live-api.md`（對外契約：起飛時帶編號）
- 建立：2026-09-21

## 現象與需求（2026-09-21 使用者裁定）

外部控制端重複執行同一條路徑時，**每一次都要算成不同的任務**，
而且**任務名稱以時間為單位自動產生**，不要求外部控制端自己想名字。

## 為什麼

系統裡「路徑（plan）／任務（mission）／架次（session）」是三個不同的東西
（見 `doc/external-live-api.md` §2.1）：路徑是一份航線，**任務是一件要做完的事**，
架次是一次解鎖到上鎖。同一條路徑飛三趟，是**三件事**，不是一件事飛三次。

本專案的主要用途正是「同一條路徑飛多趟比較訊號」（見對外任務歷史 API
「比較兩趟或多趟的訊號」）。如果三趟共用一個任務編號，那三趟的資料就疊在
同一個任務底下，`ext/missions/{id}` 的比較功能拿不出「這趟 vs 那趟」。

## 要決定的

* **名稱格式。** 建議 `{路徑名稱} {YYYY-MM-DD HH:MM}`（地面站時鐘，
  與對外 API 的時間基準一致）。同一分鐘內重複觸發要能區分——加秒數還是序號。
* **外部控制端帶了編號時怎麼辦。** 契約現在是「外部控制端在呼叫起飛時帶編號」。
  是改成「可省略，省略就自動產生」，還是「一律忽略、一律自動產生」？
  **前者相容、後者一致**，這一格要人決定。
* **我們自己的畫面要不要同步。** 目前是起飛時問操作員。如果外部走自動命名而
  畫面走人工命名，兩邊產生的任務會長得不一樣。

## 影響

* 現況下外部控制端若重用編號，多趟資料會被併進同一個任務——**而這個錯誤
  在事後幾乎看不出來**，只會發現「比較的結果怪怪的」。
* 這是對外契約的變更，`doc/external-live-api.md` 與 `external-history-api.md`
  都要一起改。
