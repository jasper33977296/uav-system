# 061 · 外部控制重複執行同一條路徑，要算成不同的任務

- 狀態：**closed**（2026-09-23；**對外契約變更**，見〈解決方式〉）
- 嚴重度：medium（任務切分錯誤會讓多趟資料混在一起，比較就失去意義）
- 位置：`apps/command/app/main.py`（`mission_fly` 的任務編號）、
  `doc/external-live-api.md`（對外契約：起飛時帶編號）
- 建立：2026-09-21

## 現象與需求（2026-09-21 使用者裁定）

外部控制端重複執行同一條路徑時，**每一次都要算成不同的任務**，
而且**任務名稱以時間為單位自動產生**，不要求外部控制端自己想名字。

## 為什麼

系統裡「路徑（plan）／任務（mission）／架次（session）」是三個不同的東西
（見 `doc/external-live-api.md` §2.1）：路徑是一份航線，**任務是一件要做完的事**，
架次是一次解鎖到上鎖。同一條路徑飛三趟，是**三件事**，不是一件事飛三次。

本專案的主要用途正是「同一條路徑飛多趟比較訊號」（見對外任務歷史 API
「比較兩趟或多趟的訊號」）。如果三趟共用一個任務編號，那三趟的資料就疊在
同一個任務底下，`ext/missions/{id}` 的比較功能拿不出「這趟 vs 那趟」。

## 要決定的

* **名稱格式。** 建議 `{路徑名稱} {YYYY-MM-DD HH:MM}`（地面站時鐘，
  與對外 API 的時間基準一致）。同一分鐘內重複觸發要能區分——加秒數還是序號。
* **外部控制端帶了編號時怎麼辦。** 契約現在是「外部控制端在呼叫起飛時帶編號」。
  是改成「可省略，省略就自動產生」，還是「一律忽略、一律自動產生」？
  **前者相容、後者一致**，這一格要人決定。
* **我們自己的畫面要不要同步。** 目前是起飛時問操作員。如果外部走自動命名而
  畫面走人工命名，兩邊產生的任務會長得不一樣。

## 影響

* 現況下外部控制端若重用編號，多趟資料會被併進同一個任務——**而這個錯誤
  在事後幾乎看不出來**，只會發現「比較的結果怪怪的」。
* 這是對外契約的變更，`doc/external-live-api.md` 與 `external-history-api.md`
  都要一起改。

## 相關

* 060（重複執行不會先飛到起始點）——同一個「重複執行」場景的另一半
* 對外任務歷史 API（`ext_history.py`）——比較功能的消費端

## 解決方式

### 先確認的：自動命名其實已經在了

不給 `mission_name` 時本來就用「`<路徑名> MM-DD HH:MM`」，同分鐘撞名加秒數、再撞加 `#2`
（`missions._pick_name`）。所以「同一分鐘怎麼區分」那一格不必決定——**原本缺的只有
「算不算同一個任務」**。

### 裁定（2026-09-23 使用者）

> 「直接設計成每次外部控制的請求都是新的 mission。雖然設計上可以一個任務含多路徑，
> 但現在不管是從前端控制還是外部控制都先**一個任務綁定一條路徑**。」

| 情況 | 以前 | 現在 |
|---|---|---|
| 帶的 `mission_id` 對到**進行中**的任務 | 掛進去 | 409 `mission_id_used` |
| 帶的 `mission_id` 對到**已結束**的任務 | 409 `mission_ended` | 409 `mission_id_used`（同一個代碼）|
| 沒帶 `mission_id`、這台機還在別的任務裡 | 沿用那個任務 | **建立新任務**，把舊的結束掉並在 `replaced` 裡說出來 |
| 我們自己的畫面 | 名稱欄空白、要人自己想 | **預先填好**「`<路徑名> MM-DD HH:MM`」（與外部同形），要改還是可以 |

### 做了什麼

* `missions.ensure` 改成**一律建立新任務**。`mission_id` 給了而且沒被用過就拿它當新編號
  （外部要對得上自己的請求）；用過就 409，訊息說它是進行中還是已結束。
* **舊任務會被結束**（資料庫的不變式：一台機一次只能在一個任務），回應帶
  `replaced: [{id, name, drone}]`——**默默結束別人的任務是不行的**。
* `missions.plan_id`（FK → plans，`ON DELETE SET NULL`）：一個任務綁定一條路徑。
  外部起飛時直接寫；畫面建立的任務在架次掛上去那一刻補寫，**已經綁了就不動**
  （不讓第二趟不同路徑的架次悄悄改掉任務的路徑）。
* `mission_busy` 從常態變成**只剩競態**（兩個請求同時替同一台機建任務）。
* 對外文件 `doc/external-live-api.md`：新增「一次執行＝一個任務」一節與錯誤表更新。

### 驗證（指令服務容器內，對真 DB，用臨時的測試機體）

第一次建立新任務且綁到路徑；**再執行一次＝另一個任務**，帶 `replaced` 指出被結束的那個、
而且那個真的有 `ended_at`；同分鐘的第二個名稱自動加秒數；重用進行中的與已結束的
`mission_id` 都被擋（`mission_id_used`／409）；沒用過的 UUID 被採用。測試資料已刪、殘留 0。

**沒驗到**：畫面上的名稱預填（要真的起飛觸發那個問框才看得到）。
