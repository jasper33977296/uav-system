# 036 · 即時頁把「沒有資料」畫成「有資料」

- 狀態：**closed**（2026-08-31 對帳收案；實作在 `3d5193f`，A 層過期顯示在 `16f5b1e`）
- 嚴重度：medium（顯示正確性；其中假座標一項在地圖上會直接誤導）
- 位置：`apps/backend/app/main.py`（廣播）、`mavlink_rx.py`（位置寫入）、
  `apps/frontend/components/MapView.tsx`、`apps/frontend/app/drones/page.tsx`
- 建立：2026-08-24

## 現象

使用者問：「為什麼斷線的無人機會顯示在即時頁面上？」

查下來是**三件不同的事**混在同一個症狀裡，其中兩件是錯的：

| # | 情況 | 現行 | 判斷 |
|---|---|---|---|
| A | 曾連上、後來斷線 | 留在畫面顯示最後已知位置 | **正確且刻意**（ui-spec 的「顯示的是最後已知位置」）——但**看不出它已經斷線** |
| B | 從未連上過 | 一樣佔著畫面，一筆資料都沒有 | **錯**。沒有「最後已知」可言 |
| C | 連著但 GPS 未定位 | 畫在 **0,0**（幾內亞灣外海） | **錯，而且最危險**——它看起來像一個有效位置 |

## 原因

**B — 主機在任何遙測之前就進了機隊，而廣播不看連線狀態。**

```python
fleet[live.drone_id] = live      # main.py:135，啟動時無條件
...
for st in list(fleet.values()):  # main.py:99，遙測廣播
    await manager.broadcast({...})          # 全部送
```

對比隔壁的登錄表廣播（`main.py:114`）就看得出落差——**它有擋**：

```python
for st in list(fleet.values()):
    if not st.connected: continue
```

同一個迴圈結構，一個擋一個不擋。不是設計上的取捨，是漏了。

**C — 位置寫入沒有分辨哨兵值。**

```python
st.lat = msg.lat / 1e7        # mavlink_rx.py:332，無條件
```

`GLOBAL_POSITION_INT` 在沒有位置估計時送的是 **lat=0、lon=0**，那是自駕儀的
「不知道」哨兵。`LiveState.lat` 的型別本來就是 `float | None`——**「不知道」是
表達得出來的**，這行卻把誠實的 `None` 覆蓋成假座標。然後地圖的過濾器是：

```js
.filter(([, t]) => t.lat != null && t.lon != null)     // 0 不是 null，會通過
```

於是機體被畫在 0,0，而 `map.jumpTo({center: [t.lon, t.lat]})` 會把鏡頭跳過去。

> **這正是 agent 端刻意避開的同一個坑**：機上訊號採樣在沒定位時讓 `lat/lon`
> 留 `None` 而不填 0,0，理由寫在 `modem.py` 的註解裡——「那不是『在幾內亞灣』，
> 是『不知道』」。地面站自己的遙測路徑反而有這個問題。

## 修法

1. **C（假座標）**：ingest 遇到 `lat == 0 and lon == 0` 時**不寫入**，維持 `None`。
   **判準用哨兵值而不是 `gps_fix`**：位置來源不一定是 GPS（室內光流、動捕都可能），
   拿「GPS 沒定位」去否定位置會誤殺那些來源。
2. **B（從未連上）**：`LiveState` 加 `ever_connected`，遙測廣播跳過它——
   **沒有產生過遙測的機，沒有遙測可以報**。註冊清單仍由 `/api/drones` 提供，
   那是另一條路徑，該顯示的照顯示。
3. **A（斷線）**：保留最後已知位置（使用者確認要），但**視覺上必須看得出來**——
   紅色外框閃爍動畫。使用者原話：「斷線後可以顯示最後已知位置，但要用紅色外匡
   動畫閃爍表示已經斷線」。

## 順帶處理：無人機頁的 `connection_url`

每一列都印著 `udpin://0.0.0.0:14540`，而且**每台機都一樣**——因為那是
**地面站自己的收聽埠**，不是該機的位址（`0.0.0.0`＝「本機所有介面都收」，
`udpin`＝「我等對方送過來」）。單埠多機設計下（issues/011）它本來就只有一個。

顯示一個對每台機都相同、又不能拿來做任何事的字串，只會讓人以為
「每台機都連到同一個地方所以壞了」。從 UI 移除。

欄位本身暫留（`POST /api/drones` 仍接受），但**已無任何讀取端**——
全庫 grep 只有寫入。日後要讓它有意義，該填的是**該機代理的端點**，
但那要等 [026](026-autopilot-driver-abstraction.md) 待決點 5 定了才知道形狀。
在那之前它是死欄位，比照 [023](023-missions-table-role-cleanup.md) 的處理方式。

## 驗證（實跑，非讀碼推論）

用防火牆規則擋掉 14540 模擬斷線（不動飛機），三種情況逐一確認：

| 情況 | 廣播內容 | 結果 |
|---|---|---|
| 正常連線 | `connected=True ever_connected=True` **lat=None** | 不再有假座標；高度與航向仍有值（氣壓計／羅盤不需 GPS）|
| 斷線但曾連上 | `connected=False ever_connected=True` | 保留最後已知位置，前端據此畫紅框 |
| 從未連上（封鎖中重啟 backend） | **0 台機** | 幽靈機不再佔畫面 |

前端 `✓ Compiled successfully`。防火牆規則已清除（殘留檢查 0 條）。

## 解決方式

`3d5193f`（A／B／C 三種情況）＋ `16f5b1e`（A 層：過期資料不得長得像即時的）。
2026-08-31 逐項對帳：

* **A 曾連上、後來斷線**：`state.ever_connected`（`state.py:34`）＋
  `MapView.tsx:520` 的紅色外框閃爍。**閃爍由本地時鐘驅動而不是 store 變動**
  ——機一斷線遙測就停、store 不再變、畫面不重繪，於是「已經斷線」會**因為
  斷線本身而顯示不出來**（`MapView.tsx:675` 的註解記著這個坑）。
  後續 `16f5b1e` 再補一層：資料過舊時把數值換成「—」並掛常駐橫幅，因為
  一個灰色的「1 m」人讀到的仍然是「它在 1 公尺」。
* **B 從未連上**：不進 fleet，幽靈機不再佔畫面（`main.py:185`）。
* **C 連著但無定位**：`mavlink_rx.py:401` 的 0,0 哨兵判定，
  **判準用哨兵值而不是 `gps_fix`**（位置來源不一定是 GPS）。

三者現在在畫面上長得不一樣，這正是本案的全部要求。
