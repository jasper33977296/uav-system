# 066 · 規劃頁：從路徑表格點進去，直接跳到地圖上那條路徑線編輯

- 狀態：**closed**（2026-09-22／23；三個待決由使用者裁定，見〈解決方式〉）
- 嚴重度：medium（規劃是每天都會做的事，現在缺一條直達路徑）
- 位置：`apps/frontend/app/plans/page.tsx`、`apps/frontend/components/MapView.tsx`
- 建立：2026-09-21

## 需求（2026-09-21 使用者提出）

**點擊規劃頁裡某一條路徑的表格列時，要能直接跳到地圖上對應的那條路徑線，
並就地編輯每個點位的參數。**

## 為什麼

現在「選一條路徑」與「編輯那條路徑的點」是斷開的兩件事。規劃的實際動作是
**看列表 → 決定改哪一條 → 改它的點**，而中間那一步沒有直達的路。

## 這一條是好幾件事的共同編輯面

一起做才划算，各自分開做會做出三套不一樣的編輯介面：

* **[065](065-round-trip-overlapping-waypoints.md) 的 A（航點列表）**——
  重疊點位選不到時那條不會失敗的路。定案要做。
* **[062](062-waypoint-hold-time-not-settable.md) 的停留秒數**——
  「編輯每個參數」本來就該包含它。
* **[063](063-waypoint-hidden-under-3d-building.md) 的建物遮擋**——
  地圖點不到時，列表仍然點得到。
* **[064](064-2d-route-preview.md) 的 2D 預覽**——表格列上的縮圖就是進入點。

## 要決定的

1. **跳過去之後的鏡頭行為**：fit 到整條路徑，還是保持當前縮放只平移？
   （路徑跨度差很多時兩者體感差很大）
2. **編輯是就地展開還是進到另一個頁面**。就地的好處是還看得到其他路徑作為
   參照；另開頁的好處是空間夠放完整的航點表。
3. **同時只能編一條，還是可以並排比較兩條**？與 `AbCompare` 的既有做法有關。

## 解決方式

### 三個「要決定的」（使用者 2026-09-22 裁定）

| | 裁定 |
|---|---|
| 編輯面放哪裡 | **進現有編輯頁**（`/plans/[id]/plan`）——那裡已經有地圖、逐點編輯與檢查；列表頁再做一套等於兩套編輯器 |
| 跳過去的鏡頭 | fit 到整條路徑（開新頁本來就是這個行為）；點列表裡某一點時 `flyTo` 那一點 |
| 同時編一條還是並排兩條 | 一次一條；並排比較已經有 `AbCompare` |

### 做了什麼

* **規劃頁點一列＝到地圖上編輯那條路徑**（連縮圖也是）。飛行紀錄改由右側 ▸ 展開
  ——以前點一列是展開紀錄，要編輯得從 ⋯ 選「離地與速度」。
* **編輯頁側欄最上面是航點列表**（065 A）：序號／類型／高度／停留，點一列就選中並飛過去，
  選取與地圖雙向同步。從零模式每列可刪、列表上方有「加上回程」。
  **降落那一列的高度寫「地面」**——剖面圖那個值是借前一點的（為了畫「平飛過去再下降」），
  照抄會說「降落點在 3.3 m」。
* 停留秒數直接顯示在列上（062 的編輯面就是這裡）。

### 驗證（headless Chrome＋CDP）

規劃頁 13 列 → 點第一列 → 進到那條路徑的編輯頁；編輯頁列表 7 列（起飛／5 航點／降落）、
停留顯示 10 s／20 s／10 s；點第 3 列 → 該列標示選中、側欄顯示 `seq 4` 且停留欄是 20。

**沒驗到**：從零模式下的刪點與「加上回程」（要先在 WebGL 地圖上點出航點，headless 下做不到）。

## 後續：實際用過之後的五項（2026-09-23 使用者）

第一次真的用這個編輯面畫線之後提出的。前三項是**我上一輪做出來的問題**：

| 提出的 | 事實 | 處置 |
|---|---|---|
| 「不懂高度基準三個選項差別」 | `離地面`＝用我方 DEM 逐點換算（還會補中繼點）；`離起飛點`＝所有點同一個相對高度；`固定海拔`＝絕對高度。**三者都是規劃時定死的數字**（與 073 的地形跟隨不同）| 選項**只留前兩個**（使用者裁定：固定海拔日常用不到，且這個場地填 3 會變成地面以下）；加上一句話講完差別的說明 |
| 「沒有操作方法設停留時間」 | 欄位**其實在**，但在右欄最底下、要先選點又要捲動才看得見 | 航點列表的「停留」欄**可以直接輸入**；右欄那個留著 |
| 列表高度與右欄對不起來 | 政策是「離地面 3 m」時，右欄寫 3、列表寫 **−1.2**——列表寫死成「離起飛點」（066 第一版的錯）| 列表跟著同一個基準，表頭寫出是哪一個 |
| 「右欄能調高度與速度了，工具列那排應該就不用」 | 工具列是**新點的預設**（改它會重算所有跟著預設的點），右欄是**把某個點變成例外**——兩件事 | 使用者裁定**拿掉**，只用右欄。新點用固定預設（3 m、1 m/s）。連帶：右欄的「下一段速度」在從零模式原本改的是政策（會動到所有點），現在改成只改那一個點 |
| 「拉條改成輸入，要能輸入 0，填完再檢查」 | 受控數字欄位直接 `Number(e.target.value)`，打字打到一半（`0`／`0.`／空白）會被吃掉 | `NumField`：**打字期間不攔**，離開欄位或按 Enter 才檢查；超出範圍夾住並**說出被改成什麼**；空白＝不改 |
| 「系統替你決定了 N 件事」那張表多餘 | 每次重算都原樣再說一次，佔掉地圖下方一整塊 | **刪掉**（`decisions` 仍由後端回、仍在狀態裡，要回復只要把表接回來）|

驗證（CDP 真的畫線）：工具列只剩高度基準／放點類型／圍欄；列表高度欄顯示「高度（離地面）」
且與右欄同為 3（修正前是 1.4／−1.2）；在列上輸入 25 → 那一列變 25；右欄 0 個拉條；
決策表不再出現。滑桿相關的兩句舊提示一併改掉。

## 第六項：放下的點被自動改成降落點（2026-09-23 使用者回報）

**現象**：畫線時放第二個點，它自動變成降落點——而使用者放的是航點。

**原因**（`plan_check.build_plan`）：沒有標降落點、也沒有選「回起飛點降落」時，
規則是**拿最後一個放的點當降落點**。所以每放一個新點，前一個變回航點、新的那個
變成降落。而且它不只是顯示：那個點**真的被改寫成降落序列**（進場點＋LAND），
航線就在那裡結束。

**裁定（使用者）**：沒有標降落點時**警告使用者，不讓它進行儲存的操作**。

**做了什麼**：

* `build_plan` 不再替操作員挑降落點；回傳多一格 `ending`：
  `home`（回起飛點降落）／`marked`（標成降落點的那一個）／**`none`（沒有結尾）**。
* 畫面：`none` 時出現警告、**「另存新檔」停用**，警告旁邊直接放兩條出路
  （一顆「回起飛點降落」，以及「在右欄把某個點改成降落點」）。
* 後端：`POST /plans/draft` 帶 `save_as` 而 `ending` 是 `none` → **422 `no_ending`**。
  **擋在這裡才是真的擋**，不只靠畫面。

**驗證**（CDP 真的畫線）：放 3 個航點 → 三個都仍是航點（修正前最後一個會變降落）、
出現警告、另存新檔 `disabled=true`；按「回起飛點降落」→ 列表多出「降落 · 地面」、
警告消失、按鈕恢復。API：帶 `save_as` 而沒有結尾回 422 且**資料庫沒有多出那一份**；
標了降落點的 `ending=marked`。

## 第七項：其他自動決定的稽核（2026-09-23）

使用者：「繼續檢查規劃頁還有沒有類似的自動決定」。`build_plan` 全部 12 項：

**純機制，不需要出聲**：起飛項、改速度項擺在第一個航點之前、MAVLink frame 對應、
手動改過的點標成「例外」（右欄已有標示）。

**有預設值但看得到也改得動**：起飛高度（沒填＝政策高度）、降落方式（垂直／逐漸）、
政策預設 3 m／1 m/s。

**原本會出聲、決策表拿掉之後變成靜音——已補**：

| | 事實 | 處置 |
|---|---|---|
| 查不到地形時**悄悄退回「離起飛點」** | 你選的是「離地面」，那幾個點算不出來；**那幾段的離地高度實際上沒被檢查過** | 後端多回 `fallback`；列表下方出現警示晶片＋ⓘ |
| **系統補你沒放的點** | 降落前的進場點、為了整段貼地插的中繼點（上限 60）。我做的航點列表還把它們濾掉，等於完全看不見 | 後端多回 `auto_points`；列表下方「系統另外補了 N 個點」＋ⓘ 說明兩種點。**仍然不列進列表**——重算就換一批，列出來也選不到 |
| **標兩個降落點時只有最後一個生效** | 前一個在航線裡是**普通航點**（飛過去、不降落），而畫面上它仍顯示「降落」——說的與做的不一樣 | 一條航線只允許一個降落點：標新的就把舊的改回航點 |

**找到但沒改（記錄下來）**：標成降落點的那個點**會被移到航線最後**（航線先飛其他點，
最後回到它降落）。列表的順序有照實反映，所以畫面沒說謊；但「移到最後」本身沒有人講。
要不要講，等使用者決定。

驗證（CDP）：畫 3 個點 → 「系統另外補了 2 個點」出現；把第 2 列標成降落點 → 降落列到最後；
再把第 3 列標成降落點 → 其餘各列回到「航點」（只有一個降落點）。API：沒有 DEM 的座標
`fallback=true`、有降落點時 `auto_points=1`（進場點）。
