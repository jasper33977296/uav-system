# 074 · 外部觸發任務「回傳失敗但實際飛了」——而且重試讓它飛了第二趟

- 狀態：**closed**（2026-09-23；**對外契約新增**，見〈解決方式〉）
- 嚴重度：**high**（呼叫端以為沒飛，飛機在飛；重試會讓它再飛一趟）
- 位置：`apps/command/app/main.py`（`/api/start`）、`doc/external-api-v3.html` §6.2
- 建立：2026-09-23

## 現象

使用者 2026-09-23：「外部觸發飛任務飛行出現 回傳失敗但實際執行成功的問題」、
「它那裡顯示 timeout」。

## 事實（`command_log` 與 `missions`／`flight_sessions`，時間為 UTC）

| 時間 | 事件 |
|---|---|
| 08:14:05 | 外部 `/api/start` → 建立任務 `1bea6f04`（external=true）|
| 08:14:11–08:15:32 | **真的飛完一趟**（離地 08:14:13，落地上鎖）|
| 08:14:24 | 伺服器回 **200**——整套歷時 **19 秒** |
| 08:16:02 | 外部**重試** → 另一個任務 `3b13b0a0` |
| 08:16:07–08:18:20 | **又飛了一趟完整的** |

`/api/start` 兩次都是 200，`mission_fly` 也都 `accepted`——**伺服器端沒有任何失敗**。
「回傳失敗」是呼叫端自己的 HTTP 逾時。

## 原因

`/api/start` 是**同步**的：上傳 → 解鎖 → 起飛 → **飛到任務起始點並等到位** →
切 AUTO，全部做完才回應。那天起始點就在腳邊，`goto_start` 只花 7 秒，整套仍要 19 秒；
**起始點遠一點，那一段就是飛過去的時間，沒有上限**。外部控制端的逾時比它短。

### 危險窗口

`_inflight_upload_block` 只擋「armed＋在空中＋模式是 mission」。
**起飛之後、切進 mission 之前那 7–14 秒，機體在 GUIDED，是放行的**——
而呼叫端的逾時（看起來 10–15 秒）正好落在這個窗口裡。重試會對一架**已經在空中**
的飛機重新上傳航線並重下指令。那天沒撞上只是因為第一趟已經落地。

061 的 `mission_id` 重用防護沒有攔住：重試用的是新的 UUID（或沒帶）。

## 解決方式

使用者 2026-09-23 裁定：**加 `wait=false`，預設維持同步**；**重試防護兩個都做**。

### 1. `wait: false`（`StartIn` 新欄位，預設 `true`）

立刻回 **202**＋`mission_id`＋`stream`，序列丟到背景跑；進度與成敗走既有的串流
（`start_step`／`start_done`／`start_failed`——這三種訊息本來就在送了）。
預設仍是同步，**舊的呼叫端行為不變**。

背景 task 自己吞例外並記一條日誌：沒有人接的例外會變成靜默的
「Task exception was never retrieved」，而失敗已經由串流送出去了。

### 2. 重試防護（兩道）

新增 `_start_step`（序列跑到哪一步），與既有的 `_start_mission` 一起用：

| 重送時 | 結果 |
|---|---|
| 帶**同一個** `mission_id` | **202** `already_running: true`＋目前的 `step`——「你那一次其實成功了，現在跑到這裡」。**不重新起飛** |
| 帶**別的** `mission_id`，或**不帶** | **409** `start_in_progress`，訊息說出跑到哪一步、是哪個任務 |

同一個編號重送回 202 而不是 409，是因為**呼叫端要的答案是「我那一次到底成功了沒」，
而答案是「成功了，正在跑」——那不是錯誤**。

## 驗證（2026-09-23）

`scripts/test-start-retry-guard.py`，**不碰飛機**：把「序列進行中」的狀態塞進模組
再呼叫 `_start`，防護若有效就會在碰到飛控之前回覆，所以整支測試不送出任何 MAVLink。
10 項全過：沒有序列時不誤擋、不同編號 409 且說得出步驟與下一步、同一編號 202 且明說
沒有重新起飛、沒帶編號也不會靜默放行。

`wait` 參數進了 OpenAPI；帶 `wait=false` 而路徑不存在仍然 404（不會起飛）。

**沒驗到**：真的飛一趟時 `wait=false` 的完整行為，以及重試防護在真實序列中被觸發
——那需要讓飛機真的起飛。等下次實飛時一併看。
