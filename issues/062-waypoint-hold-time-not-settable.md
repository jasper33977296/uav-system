# 062 · 規劃路徑時設不了「在這個點停留幾秒」

- 狀態：in-progress（**編輯端與標記端都完成 2026-09-22**；規劃頁的實際點選操作與縮圖／列表標示未驗，見〈解決方式〉）
- 嚴重度：medium（量測流程需要定點停留，現在做不到）
- 位置：路徑規劃 UI（`apps/frontend/app/plans/`）、航線資料結構
- 建立：2026-09-21

## 現象

規劃路徑時**無法設定讓無人機在特定點位待一段時間再飛往下一個點**。

## 這件事已經做了一半

系統的其他部分**已經認得停留時間**——`libs/mission_time.py` 估算飛行時間時
就在讀它：

```python
# 停留：`NAV_WAYPOINT` 的 param1、`NAV_LOITER_TIME` 的 param1（秒）
hold_s += float(p1)
...
assumptions.append(f"含航點停留合計 {hold_s:.0f} 秒")
```

也就是說：**匯入的 `.plan` 帶停留時間我們讀得懂、算得進去，
但我們自己的規劃介面產不出來。** 缺的是編輯端，不是資料模型。

## 為什麼需要

訊號量測常常要在一個點停住量一段時間——飛過去再飛走，那個點上只有一兩筆樣本。
這是本專案的核心用途，不是附加功能。

## 修法建議

* 航點編輯加一格「停留秒數」，預設 0，寫進 `NAV_WAYPOINT` 的 `param1`。
* `MissionThumb3D` 與路徑列表要看得出哪些點有停留（**否則規劃完看不出來**）。
* 飛行時間估算已經會算進去，不用改。
* 要不要支援 `NAV_LOITER_TIME`（真正的定點盤旋）另議——`NAV_WAYPOINT` 的
  param1 在 Copter 上就是到點後停留，多數情況夠用。

### 裁定（2026-09-21 使用者）：**停留期間的樣本要標記出來**

停 30 秒＝那個點上多出約 30 筆樣本，沿航線里程全都一樣。對訊號研究這是好事
（同一點多次取樣看得出變異），但**不標記的話，分析端分不出「機在這裡停了 30 秒」
與「這裡的樣本特別密」**——而後者可能是別的原因造成的。

所以停留是一等公民：航線上有停留的點，**任務歷史 API 要說得出「這一段是靜止
量測，共 N 秒、M 筆」**。

> 使用者的原則（2026-09-21）：**整個系統的呈現要與事實貼齊。**
> 這與「估的與量的要分得出來」、036 的顯示誠實是同一條線。

## 相關

* `libs/mission_time.py`——消費端已就緒
* 064（2D 預覽圖）——停留點要在預覽上看得出來

## 解決方式

### 1. 編輯端：設得出來、存得進去、看得出來

* **後端**：`PlanOverride.hold`（既有航線逐點覆寫）與 `DraftPoint.hold_s`（從零畫），
  0–3600 秒（`plan_check.HOLD_MAX_S`，「這麼長一定是打錯」的界線，不是飛控上限）。
  寫進 `NAV_WAYPOINT` 的 param1——既有的存檔與上傳路徑本來就帶 `p1`，一路到飛控。
  **對起飛、降落、改速度項設停留回 422**：那些指令的 param1 意思不同，照寫會改到別的東西。
  從零模式下系統補的中繼點不帶停留（`_fill_terrain` 產生新 dict，不會繼承）。
* **剖面帶 `hold_s`**（`route_profile`）。這一條翻出來的：`260921-straight-hold-v2`
  **本來就有 10／20／10 秒的停留**（QGC 設的），以前規劃頁完全看不出來。
* **前端**：逐點編輯器加「到點停留（秒）」（數字＋0–120 的滑桿），只在一般航點出現；
  3D 場景上有停留的點多兩圈平躺的細環（與選取的單圈光暈分得開，顏色不借橘）。
* 飛行時間估算本來就讀 param1（`mission_time`），不用改——測試確認多停 30 秒＝估算多 30 秒。

### 2. 標記端：任務歷史說得出「這一段是靜止量測」

`apps/backend/app/holds.py`＋`ext_history.mission_signal`：每一趟多 `holds`
（規劃秒數、**量到的**時段與秒數、那段裡幾筆、`note`），每筆樣本多 `hold_seq`。
對外文件 `doc/external-history-api.md` §4.2。

**實作時被實飛推翻的假設**：原本打算拿 `waypoint_reached` 當「到達」、往後算規劃秒數。
對 09-21 兩趟實飛時發現 **ArduCopter 4.7 的那則事件在停留結束時才來**，而且報的序號
是停留點**後面那一項**（改速度指令）。照原設計，每一段都會標在停留之後、機已經在飛的
那幾秒上。改成**量出來的**：

* 是哪一點：機端序號不超過事件序號的最後一個 `NAV_WAYPOINT`（事件報航點本身或
  後一項都對得上）；序號換算走驅動的 `wire_seq`，**不認得自駕儀就不換算**
  （未知驅動會安靜地回 0 偏移）
* 是哪一段：事件前後 3 秒內、地速連續低於 0.3 m/s 的那一段，往兩邊延伸到開始動為止
  ——**不假設事件是起點還是終點**
* 量不到就照實說：沒收到到點事件／有事件但看不出有停／停得不到規劃的一半
