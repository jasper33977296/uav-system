# 058 · 別人改了飛控參數，我們的畫面不說——2026-09-21 花了很久才找到

- 狀態：open
- 嚴重度：**high**（會把人導向完全錯誤的排查方向；實際損失數小時）
- 位置：`apps/backend/app/mavlink_rx.py`（收 `PARAM_VALUE` 的地方）、
  即時頁的預檢呈現（`SimpleHud.tsx`／`lib/prearm.ts`）
- 建立：2026-09-21

## 現象

2026-09-21：無人機無法解鎖、校正也跑不完。排查花了很久，而原因之一是
**飛控上的參數被我們系統以外的人改過**，我們的畫面完全沒有提示這件事。

畫面上看得到的只有飛控吐出來的預檢字串：

```
PreArm: Vehicle breaching Polygon fence
PreArm: Fences enabled, but none selected
PreArm: Fence requires position
```

而真正的事實是 `FENCE_ENABLE=1`、`FENCE_TYPE=5`、`FENCE_TOTAL=6`、
`FENCE_ALT_MAX=6`——飛控裡存著一個**沒有人記得的六點多邊形**，機子站在它外面。
要知道這件事，得 ssh 上機器、停代理、拿 tlog 或直接問飛控。**畫面一個字都沒說。**

## 原因

1. **我們不記錄參數，所以說不出「它變了」。** `mavlink_rx` 收得到 `PARAM_VALUE`
   （代理開機會讀一輪，地面站要參數時也會走這條），但那些值沒有被留存，
   自然也沒有「上次是多少、誰改的、什麼時候」。
2. **預檢字串被原樣轉出。** `PreArm: Vehicle breaching Polygon fence` 對飛控來說
   是完整的，對操作員來說少了最重要的一半：**哪個圍欄、在哪裡、我離它多遠**。
3. **沒有「這台機的設定和我們以為的不一樣」這個概念。** `set-fc-params.py` 的
   PLAN 表就是我們對這台機設定的主張，但它只在有人手動跑的時候比對一次，
   平常沒有任何地方拿它跟現況對帳。

## 影響

排查方向被帶偏：畫面說「圍欄」，但因為看不到圍欄的內容與自己的相對位置，
第一直覺會往 GPS／定位／校正去猜——而那天確實同時有校正跑不完的問題（059），
兩件事混在一起，更難拆開。

**這類失效會重演**：只要有第二個人碰得到飛控（用 Mission Planner、MAVSDK、
或另一支腳本），而我們既不記錄也不比對，下一次一樣是從零猜起。

## 修法建議

按價值排序，三條可以獨立做：

### A. 參數快照與變更事件（建議先做）

`mavlink_rx` 收到 `PARAM_VALUE` 就存進 DB（`drone_id` + 參數名 + 值 + 時間）。
值與上一筆不同就發一則 `param_changed` 事件進事件流。**這是最小的改動，
而且立刻回答「它是什麼時候變的」**。

注意：代理開機會讀一整輪 1244 個參數，**第一輪不該噴 1244 則事件**——
首次建檔與後續變更要分開。

### B. 拿 PLAN 表對帳

`set-fc-params.py` 的 `PLAN` 已經是「我們主張的設定」。把它做成後端也讀得到的
一份資料，收到參數時比對，不符就在即時頁掛一條「機上設定與預期不同」。
**021（參數快照）與這條是同一族**，可以一起規劃。

### C. 預檢字串加上我方知道的脈絡

畫面顯示 `Vehicle breaching Polygon fence` 時，旁邊補上我們手上就有的資訊：
圍欄型別、頂點數、機目前在圈內或圈外、距離多遠。**不要改寫飛控的原句**
（那是權威），是在它旁邊補。
