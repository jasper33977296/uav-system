# 植被（OSM）：樹、行道樹、樹林

`scripts/fetch-vegetation.py` 在**有網路的時候**抓進來的離線資產，與
`data/buildings/` 同級：**不進 git**，佈署前自己抓。

    python3 scripts/fetch-vegetation.py 24.7734 121.0459 --radius-m 800

即時頁用它畫「可能的障礙物」（ui-spec §2.4e）。

## 這份資料能回答與不能回答的

**能**：「這裡標了一棵樹／一片林。」
**不能**：「這裡只有這些樹。」也不能：「那棵樹有多高。」

本場域（2026-10-13 向 Overpass 實查）抓到的是：

| 類 | 數量 | 幾何 |
|---|---|---|
| 樹 `natural=tree` | 5 | 點 |
| 行道樹 `natural=tree_row` | 3 | 線 |
| 樹林 `natural=wood` | 3 | 面 |
| **有高度的** | **0** | — |

現場顯然不只 5 棵樹。所以這份資料的兩個限制都必須跟著它上畫面：

* **高度全缺 → 一律畫在地面，一棵都不拉起來。** 樹的高度正是「會不會
  擋到」的全部重點；拉一個猜的高度上去，等於用畫面保證一件沒人量過的事
  （同 `data/buildings/README.md` 的 `unknown`：猜到的與量到的是兩件事）。
* **覆蓋率低 → 「沒有標記的地方不等於淨空」要寫在圖例的 ⓘ 裡。**
  端點 `GET /api/vegetation/near` 的 `meta.complete` 恆為 `false`。
  少了這句，使用者會把它讀成樹的清單——那比沒有這個圖層更糟，
  因為它看起來像查過了。

## 已知的取捨

* **只收會擋路的那幾類**（樹／行道樹／林／灌叢／果園）。草地、花圃不收：
  不是障礙物，畫上去只會讓真正該看的東西更難找。
* **單棵樹畫成固定像素的圓，不是樹冠。** OSM 沒有樹冠直徑，照比例畫
  等於憑空給它一個大小。
* **multipolygon 的林只取第一個 outer 環**（同建物 §9-D，忽略內庭）。
* **距離量到幾何本身，不是外接框。** 場地那片林的外接框罩住半個場地，
  用框距會回「0 m」，讀起來就是「你在林子裡」。
* **飛控不會因為這份資料變安全。** 與建物一樣，這只是地面站這端的呈現。
  要真的回答「樹會不會擋到」，前提是實地量測（光達／攝影測量）。
