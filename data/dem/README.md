# 地形圖磚（DEM）

`libs/terrain` 從這裡讀 SRTM `.hgt`，供上傳前的**離地高度預檢**使用
（issues/047 §1-B）。容器以唯讀掛在 `/srv/dem`（`DEM_DIR`）。

## 為什麼不進 git

一塊 1 弧秒圖磚 **25 MB**，而它一年也不會變。放進 git 等於讓每個 clone
都拖著它跑，還會把 repo 撐大到 push 不動。所以 `.gitignore` 擋掉 `*.hgt`，
**只有這份說明進版控**。

## 怎麼補

在**有網路的地方**先抓好，跟著機器帶到現場（現場是離線的）：

```
python3 scripts/fetch-dem.py 24.7738 121.0461        # 一個點所在的圖磚
python3 scripts/fetch-dem.py 24.7 121.0 24.9 121.3   # 一個範圍
```

來源：AWS `elevation-tiles-prod/skadi`（SRTM 1 弧秒，公開、免金鑰）。

## 沒有圖磚會怎樣

**預檢會說「離地高度沒有檢查」，不會說「通過」。** 查不到高程與
「離地很夠」在資料上長得一樣（都沒有 problem），所以那句話是必要的。

## 這份資料能回答什麼、不能回答什麼

* 水平解析度約 **30 m**：能防「整片地比起飛點高了幾公尺」。
* 防不了「前面有個 1 m 土堆」——一格之內的東西它不知道。
* 它是一份**被 30 m 格子抹平的表面**：C 波段雷達的回波來自樹冠與屋頂，
  只部分穿透。**既不是乾淨的地面，也不是能用的障礙物圖**——有樹的地方
  地面被抬高，而一棟樓會被周圍地面平均掉（見 `doc/field-3d-model-design.md` §3）。
* 絕對高程誤差（LE90 約 16 m）在本系統的算法裡會相減消掉，
  剩下的是同塊圖磚內的相對誤差（數公尺）——理由見 `libs/terrain` 開頭。
* 真的要貼地飛，需要的是**測距儀**（本機 `RNGFND1_TYPE = 0`），不是更好的 DEM。
